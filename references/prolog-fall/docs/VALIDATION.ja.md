# Windows での検証記録

2026-10-26、この PC の Windows x64 上で、SWI-Prolog 10.0.2 と raylib 6.2 を実行しました。ヘッドレスな規則テストに加えて、raylib の実ウィンドウを開き、規定フレーム数でスクリーンショットと測定値を保存して終了する検査を行っています。

## 規則と問い合わせ

`scripts/test.ps1` の **54 件すべてが成功**しました。約 0.3 秒分のテスト実行に、Prolog の起動時間が加わります。

- 七種類の形、壁・床・衝突、回転失敗、最初の壁蹴り候補の選択。
- 座標が決まった検査と、X や向きが未定な制約、順不同のセルから種類・回転・位置を求める検査。
- 手書きの期待座標と盤面を使った一行・二行消去、消去後の圧縮、スコア。
- バッグ二周、ホールドの再使用制限と交換、重力、固定待ち、15 回のリセット制限、ゲームオーバー、同じ操作列の再実行。
- 探索で返したすべての手順を共有する移動規則で再生し、同じ姿勢に着地すること。
- O を置けて支えもある空洞に、上から操作しては届かない反例。屋根は一部だけを覆い、最初から完成した行はない。
- 姿勢の回転番号を探索中は残し、固定候補をセル集合でまとめた後には重複がないこと。

`scripts/query-demo.ps1` の実測例では、デモの 614 姿勢を調べて、34 個の異なる固定セル集合を返しました。探索時間は約 21 ms。最初の候補は `pose(t,0,3,18)`、下移動 19 回、一行消去です。空洞の例は 628 姿勢を調べ、静的に置ける目標姿勢が探索結果にないことを確認しました。問い合わせ時間は実行ごとに変わります。

## ネイティブ描画

次の二つを実行し、終了コード 0 を確認しました。

```powershell
.\scripts\run.ps1 --demo --query --seed 42 --smoke 120 `
  --screenshot "$PWD\.scratch\demo.png" --report "$PWD\.scratch\demo-smoke.json"
.\scripts\run.ps1 --seed 42 --autoplay --smoke 180 `
  --screenshot "$PWD\.scratch\play.png" --report "$PWD\.scratch\play-smoke.json"
```

| 検査 | 結果 |
| --- | --- |
| デモ問い合わせ画面、120 フレーム | 平均フレーム間隔 17.09 ms、表示 60 FPS。盤面・文字・候補枠の画像を確認 |
| 通常プレイ、180 フレーム | 平均フレーム間隔 16.65 ms。回転・横移動・ホールド・五個の固定を実行。スコア 152、プレイ継続 |

最終の静的 CRT ビルドでも、問い合わせから通常プレイへ戻る 160 フレームの検査を追加しました。アプリケーションのキー操作と共有する命令の振り分けに検査用の入力を渡し、絞り込み一回、候補の切り替え二回、Enter に相当する再生開始、19 回の移動、一回の再生完了・固定を記録しました。一行が消え、通常プレイへ戻っています。平均フレーム間隔は 16.97 ms、最大は表示待ち込み 31.66 ms でした。画像は `.scratch/replay.png`、記録は `.scratch/replay-smoke.json` にあります。

この経路は `scripts/smoke.ps1` で再実行できます。スクリプトは結果の回数と行消去を検査し、証拠を `.scratch/smoke` に保存します。デスクトップにキーを送る検査ではありません。

測定値の `work_and_pacing` は `EndDrawing` の表示待ちを含みます。純粋な規則計算の処理時間ではありません。`--autoplay` は検査用の操作注入です。キーの押し心地や長押しの人間の評価を代替するものではありません。`--smoke` は指定フレームで必ず閉じ、常駐処理を残しません。

確認側は実ウィンドウが存在することを独立に確認しましたが、Computer Use のウィンドウ取得で承認処理が時間切れとなり、実際のキー入力は送っていません。別経路でこの制限を迂回していません。したがって物理キーが届くこと、長押しの感触、フォーカス移動を伴う使い心地は未確認です。

上の段落は初回の自動検査時点の記録です。その後、同じ2026年10月26日に、オーナー本人から「普通にゲームとして動いとるのはもちろんのこと、Qでの探索モードも機能しとる」と実プレイの報告がありました。通常プレイとQの基本動作について、本人の確認が加わっています。全キー、長時間の操作感、フォーカス移動を含めた網羅的な手動検査まで行ったという意味ではありません。

`scripts/setup.ps1` は取得済みアーカイブからの再展開・再ビルドを `C:\Windows\System32` を作業フォルダーとして成功しました。最終の描画 DLL は `libswipl.dll`、`raylib.dll`、`KERNEL32.dll` だけを直接読み込み、追加の Visual C++ ランタイムに依存しません。Windows システムの PATH だけを残した起動、および空白を含む別フォルダーへ展開したバンドルでの 54 テストと DLL の読み込みも確認しています。

## この記録で確かめていないこと

全盤面に対する形式的な正しさ、SRS 準拠、時間制約付きの解法、別 PC の GPU・ディスプレイ倍率、長時間の遊びやすさは証明していません。固定サイズの画面、簡易壁蹴り、グラフ探索の範囲を公開し、反例を含む有限の検査として扱います。

画面を開く実行形が Prolog 主体であることはソースと起動経路で確認できます。しかし「Prolog ならではの考え方を読者が身につけた」という学習成果は、この実装・テストからは判断できません。
