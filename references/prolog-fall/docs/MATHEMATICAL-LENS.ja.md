# Prologでテトリスを作ると、何を問い直せるか

四つの空きマスを指して、「ここにぴったり入るピースは何か」と尋ねる。答えがT字なら、続けて「いま落ちているT字を、そこまで運べるか」と尋ねる。運べるなら、その操作列を画面で再生する。この試作では、形の関係と移動の規則を共有して、この一連の問いを実行できるようにした。

最初に見えてきたのは、テトリスには少なくとも三種類の「可能」があることだ。形が収まること、操作をつなげて到達できること、時計が進むプレイで間に合うこと。それぞれを別の数学的対象として扱うと、Prologで何を記述し、何を探索しているかがはっきりする。

以下は実装と実行結果から組み立てた考察である。一般のゲームでの優位性や、全盤面について機械検証された定理を主張するものではない。

## 1. 空きマスからピースを求める

次は、この実装で実行できる問い合わせである。四つの座標の順序には意味がない。

```prolog
?- findall(Pose,
           cover_cells([6-9,5-10,5-8,5-9], Pose),
           Poses).
Poses = [pose(t,1,4,8)].
```

結果は「T字、回転番号1、原点(4,8)」。ピースの種類・向き・位置を先に決めてから四マスを計算する代わりに、四マスを先に与え、残りを求めている。描画と衝突判定にも使う `piece_cells/5` が、この問い合わせの形を定める。

数学的には、種類と回転を $k,r$、原点を $x,y$、その向きの形を $S_{k,r}$ とすると、占有するセル集合は

\[
C(k,r,x,y)=\{(x+d_x,y+d_y)\mid(d_x,d_y)\in S_{k,r}\}.
\]

描画では左辺の引数を決めて右辺を得る。今回の逆向きの問い合わせでは、右辺に一致する引数を求める。`cover_cells/2` は四セルの対応を有限個の順列で調べ、同じ座標の関係に渡す。

盤面に置ける条件も、座標を先に一つに決める必要はない。各ピースセル $c$ と各既存セル $b$ について、重ならない条件は

\[
c_x\ne b_x\;\lor\;c_y\ne b_y.
\]

これを盤面の範囲条件と一緒に課す。`legal_pose/3` は未定の座標に有限領域制約を加え、`labeling/2` が具体的な座標を列挙する。形と回転の事実には有限の分岐があるが、座標の制約と座標の全列挙は分けている。この区別は、[SWI-PrologのCLP(FD)説明](https://www.swi-prolog.org/pldoc/man?section=clpfd-search)にも対応する。

例えば底の(4,19)だけが埋まった盤面にO字を置くとき、可能な原点Xは `[-1,0,1,4,5,6,7]` になる。単に成功・失敗を返す判定から、条件に合う値の集合を求める問いが生まれる。盤面自体は決まっている、という入力条件は残る。

## 2. 形の条件と、到達の条件は違う

下二行の左右にO字を四個置き、中央に幅二マスの空洞を残す。その上にI字を横に渡す。空洞にはO字が収まり、床にも支えられる。しかし、上からそこへ運ぶ経路はない。この盤面には、初めから完成して消える行もない。

`cavity_fixture/3` の反例を実行すると、目標は `legal_pose/3` と `supported/2` に成功する一方、開始位置から調べた628姿勢には現れない。ここでは「収まる」を調べる述語だけでは、操作できるゲームの可能性を決められない。

固定した盤面を $B$、開始姿勢を $p_0$ とする。一歩の操作を

\[
E_B(p,a,q)\quad\text{「姿勢pで操作aをすると姿勢qになる」}
\]

と書く。実装では `move_pose/4` である。到達可能集合 $R$ は、次の操作を繰り返して増やした最小の集合になる。

\[
F_B(X)=\{p_0\}\cup\{q\mid p\in X,\ E_B(p,a,q)\text{となる}a\text{がある}\},
\qquad R=\mu X.F_B(X).
\]

これは集合の包含順序での最小不動点である。実装は幅優先探索でこれを計算する。Prologに再帰を書けば自動でこの探索順になるわけではなく、キューと訪問済み集合を明示している。

今回、一種類についての姿勢の候補は高々 `4 × 13 × 24 = 1248` 個で、一歩の操作は五種類。実際には壁や既存ブロックによりさらに減る。全姿勢をキーにして一度ずつ訪問するため、この範囲の探索は有限である。通常の深さ優先探索で左右移動を繰り返してしまう問題を、入力領域と探索方法の両方で抑えている。

そこから、下へ進めず、四セルすべてが見える位置にある姿勢を取り出すと、固定候補になる。デモでは614姿勢から34種類の固定セル集合を得た。親側でも問い合わせを実行し、約22.4 ms、最初の候補が一行消去になることを確認した。これはこのPC・この盤面での測定である。

## 3. 操作列は、到達を示す証拠になる

探索結果には、`[down,down,...]` のような操作列を付ける。開始姿勢から各操作を `move_pose/4` に渡し、最後に目的の姿勢へ到達することを確かめる。

この確認には簡単な帰納法がある。開始姿勢は合法であり、一歩の規則は合法な次姿勢だけを認める。したがって、その規則でつないだ有限の操作列は合法な姿勢をたどる。実装した規則が意図したテトリスを正しく表すかは別に点検する必要があるため、壁・床・回転・行消去には手書きの期待値を使ったテストも用意した。

回転で壁にぶつかった場合、今回のゲームは補正候補を順番に調べ、最初に成功したものを採用する。探索だけが任意の補正を選べると、プレイヤーにはできない動きを「解」として返してしまう。そこで、探索も再生も通常プレイも、同じ順序を持つ移動規則を使う。

また、幅優先探索が最小化するのは一操作を一単位とした回数である。長押し、反応の難しさ、経過時間を最小化したわけではない。操作列を保存しておけば、後から別の費用や時間条件で評価できる。

## 4. 同じ四マスでも、姿勢は一つとは限らない

水平なI字の同じ四マスには、例えば `pose(i,0,4,11)` と `pose(i,2,4,10)` が対応する。O字には四つの回転番号が残る。画面上で同じ四マスを占めるという同値関係

\[
p\sim q\iff C(p)=C(q)
\]

を考えると、一つの見た目に複数の姿勢表現が属することになる。

ここで重要なのは、見た目が同じだからといって、探索中に表現を消してよいとは限らないことだ。回転の原点や補正規則が次の一歩に影響するなら、姿勢をセル集合へまとめる操作が遷移を保存するか、別途確かめる必要がある。

今回の実装は、探索中は種類・回転・原点を残す。到達集合を求め終えた後で、表示する固定候補だけをセル集合でまとめ、到達を示す操作列を一つ残す。O字の重複を画面から省けても、回転番号を探索から省いてよいという主張にはしない。

「何を同じ状態として扱うか」は表示上の都合だけではない。ゲームの操作を保存する同一視になっているかが、数学的な問いになる。

## 5. 時計を戻すことと、関係を逆向きに尋ねること

一行だけ埋まった盤面と、二行埋まった盤面は、どちらも行消去後には空になる。`projection_witness/3` は10セルと20セルの二つの入力を作り、この結果を確かめる。盤面だけを見る行消去は単射ではない。

これは「Prologでは逆向きに問い合わせられない」という話ではない。逆向きの問いの答えが、複数あり得るという話である。関係として以前の盤面の候補を求められても、それだけで実際に起きた過去を一つに決められるわけではない。今回の例では、消した行数を記録すれば二つを区別できる。何を観測・保存したかが復元の可否を変える。

実時間のプレイにも別の境界がある。通常プレイでは重力、固定までの残り時間、入力の繰り返しなどが状態に加わる。現在の探索はそれらを含まない。ゲーム画面のEnterで手順を再生するときも、重力と固定待ちは止めている。

同じピース・同じ盤面でホールドを使わない範囲なら、時間を含む実際の移動を、時間を消した操作列として表せるように設計するのが自然だ。その場合、時間なしの到達集合は可能性を広めに含み、時間内に実行できる集合とは一致するとは限らない。この包含関係の形式検証や、固定時間も含む探索は、今回まだ実装していない。

`\+/1` にも注意がいる。これは「証明の試みが有限時間で失敗する」という意味であり、未定の変数を含む問いに一般的な否定として使えるわけではない。[SWI-Prologの定義](https://www.swi-prolog.org/pldoc/man?predicate=%5C%2B%2F1)に沿って、支えの検査などでは決まった盤面・姿勢を入力する。Cの描画、キー入力、時刻取得も論理的に巻き戻る操作ではない。

## 今回得た土台と、次に問えること

今回できたのは、関係の記述、有限の到達探索、時間の進むゲームを、一つの動く成果物で見比べる土台である。形の定義を共有して問いの向きを変え、移動規則を共有してプレイと操作列の探索を結び付け、両者が扱わない時間条件を明示した。

次に深く掘るなら、「一つの成功手順」と「先の分からない状況に対応する戦略」の差が有力である。現在の探索は、いまのピースについて成功する操作列が存在するかを尋ねる。未知の次ピースまで考えるなら、「いま一手を選び、次にどのピースが来ても、その後に適切な手を選べるか」という量化の順序が現れる。

\[
\exists a_0\;\forall k_1\;\exists a_1\;\cdots
\]

これは将来の研究候補であり、現在の34候補がこの戦略を解いているわけではない。確率で評価するか、最悪の場合に備えるかでもゲームの問いは変わる。

fp-gameとの接点も、この区別を確かめてから考えられる。「許される関係」「その中から次の一手を選ぶ規則」「壊してはいけない条件」「観測すると同じに見える状態」をどう対応させるか。今は統合の形式を先に決めず、Prologのプログラムそのものに、この問いを試せる足場を残した。
