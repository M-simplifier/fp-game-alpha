実装から考える、Prolog のゲームづくり

Prologでテトリスを作ると、
何が見えるか

Qを押すと、いまのピースが届く着地点が並ぶ。選ぶと、そこへ運ぶ手順まで動く。
同じゲームの規則に、どんな問いを渡していたのだろう。

このページでは、動くゲームの盤面を足場に、Prologの記述と数学を一つずつつなげる。

01

「ここへ運べる」の答えを、一手ずつ見る

このT字を、下の三マスのくぼみに入れる。下へ19回動かせば一行が消える。Qの答えには、着地点だけでなく、開始位置からそこへたどる操作列も入っている。

このHTMLの動きは、実際のPrologの答えの再生。生成時にネイティブのSWI-Prologで問い合わせ、全手順をゲームの規則で検査してから記録した。ブラウザー内で別の探索器を動かしているわけではない。オフラインで読める。
Q / 記録された34の着地点

横10 × 縦20。上の点線部分は隠れ行 −4〜−1。
白い枠：候補の着地点 / 色付き：現在の姿勢

ここでの一手は「左・右・下・右回転・左回転」の一操作。再生速度は説明用で、実プレイの所要時間を表さない。

候補を変えてみよう。「横移動と回転のある例」では、まず横へ運び、途中で向きを変える。画面の四マスは、各操作が返した姿勢を順番に表示している。

遊ぶときと調べるときで、移動の規則を共有する

遊ぶ側は「左を押した。次の姿勢は？」と尋ねる。探索する側は、左・右・下・回転を試し、「この一歩を重ねると、どこまで行ける？」と尋ねる。move_pose/4 は両方から呼ばれる、同じ一歩の規則だ。

これは実際の左移動の節。原点Xを一つ減らし、その姿勢が盤面に置けるかを確かめる。探索の答えを再生するときも、同じ述語を通して各一歩を確認する。

操作列が「証拠」になる範囲

開始姿勢が合法で、一歩の規則が合法な次姿勢だけを返すなら、その一歩をつないだ有限の列も合法な姿勢をたどる。これが手順を再検査できる理由だ。ただし、共有した規則そのものに誤りがあれば、探索も再生も同じ誤りを共有する。壁・床・回転・行消去には、別に手書きの期待値を使う検査を置いている。ゲーム全体の機械検証済み定理とは区別する。

02

決めていない値を、問いの中に残す

普通は「T字をこの位置に置くと、どの四マスを占めるか」を計算する。では、四マスだけを先に示し、種類・向き・位置を全部未定にしたらどうなるか。

下の四つの例は、実際の cover_cells/2 に渡したものだ。Tには一つの答え、Iには二つ、Oには四つの姿勢表現がある。離れ離れの四マスには、答えがない。

四マスを、ぴったり覆う姿勢は？順番は問わない / 四マスは決まっている

X-Y は、このコードで座標対を表す項。たとえば 6-9 を、ここでは「(6,9)のセル」として使う。自動で引き算する場所ではない。

Prologの「値」は、まだ穴があいていてもよい

pose(t,1,4,8) は、T字・回転番号1・原点(4,8)という項。pose(P,R,X,Y) なら、四つの場所がまだ未定だ。大文字から始まる名前は変数で、条件に合う値を受け取れる。t や o のような小文字の名前はアトムという定数になる。

二つの項の形と中身を、矛盾なくそろえる操作が単一化だ。次の問いでは、一つの Pose に二つの記述を同時に合わせる。

?- Pose = pose(t,R,X,Y),
   Pose = pose(P,1,4,8).

P = t, R = 1, X = 4, Y = 8.

ここで「関数の返り値」という場所を一つに固定していない。P を先に決めても、四マスを先に決めても、対応する関係に条件を渡せる。ただし、どの引数を未定にできるかは述語ごとに違う。今回の cover_cells/2 は、四つのセルが決まっている呼び方に限っている。

= は単一化、#= は整数の制約

同じ「等しい」ように見えても、扱うものが違う。下の二つは、ネイティブのPrologで確かめた出力だ。

A = 2+3

2+3 という項にそろう。ここでは計算しない。

A #= 2+3

整数の関係を課す。この場合はAが5に決まる。

この試作では、局所座標と原点を #= で結ぶ。原点からセルを求めるだけでなく、セルが決まったときに原点へ条件を戻すこともできる。これは整数の制約を扱う CLP(FD) の役割だ。

Head :- A, B.
AとBが成り立つとHeadが成り立つ、という節。実行するときは体を左から試す。
R in 0..3
Rを0〜3の整数に限る。この有限の範囲が、後の列挙の土台になる。
maplist(...)
四つの局所セルそれぞれについて、座標を結ぶ同じ関係を課す。

候補を試し、条件に合わなければその分岐で決めた値を戻し、別の候補へ進む。これがバックトラッキングの基本的な働きだ。上のIやOの「次の解」は、その代替解を記録した順で見せている。別の答えを探すことと、ゲームの過去へ戻ることは違う。 通常の =/2 の意味は SWI-Prologの定義でも確認できる。

値を一つ選ぶ前に、条件を絞る

同じ legal_pose/3 に、Xを決めて渡すか、未定のまま渡すか。

底の(4,19)だけが埋まっている。Oの原点は、見た目の左端より一マス左。

X=4：実際に置ける。

値が決まった検査

?- legal_pose([cell(4,19,j)],
              pose(o,0,4,18), Cells).
Cells = [5-18,6-18,5-19,6-19].

原点X=4なら、Oは既存ブロックの右に収まる。X=2なら四セルの一つが(4,19)と衝突し、この問いは失敗する。

ここは、実行して初めて分かった大切な点だ。 境界の制約でXの領域は13個から9個へ狭まる。一方、この実装で衝突の制約を加えただけでは、Xの領域表示はまだ -1..7 のままになる。X=2,3は衝突条件にすでに反するが、Xだけの表示には残っている。

Xの範囲表示と、残っている制約全体と、条件をすべて満たす解の集合は違う。Xと結ばれた各セルの変数に条件が残り、labeling/2 が具体的なXを選ぶ段階で、2と3が失敗する。最終的な答えは [-1,0,1,4,5,6,7]。途中の変数の領域表示は、全解の一覧とは限らない。

実際に残った制約と、呼び出し方の境界を見る

表示中のAは元のXに対応する。ほかの変数は、Xに1や2を足したセル座標に対応する。これは今回のSWI-Prolog 10.0.2と実装で観測した伝播の結果であり、どんな制約でも同じ強さで絞れるという保証ではない。

legal_pose/3 は制約を課し、enumerate_pose/3 や呼び出し側の labeling/2 が座標を列挙する。形と回転には有限個の事実の分岐がある。制約の記述と全列挙を分ける考え方は、公式の説明にもある。

03

形が収まっても、そこへ運べるとは限らない

下の中央に、O字がぴったり入る幅二マスの空洞がある。床にも支えられる。でも、その上には横長の屋根がある。いま上にいるO字を、この空洞へ運べるだろうか。

屋根を外して比べてみよう。変わるのは、空洞に「置けるか」ではなく、そこへ入っていく操作のつながりだ。

同じ目標 / 屋根だけを変える

下5行の拡大。白い枠が目標のO。屋根は完成した一行ではなく、中央の四マスだけ。

目標に収まる・支えがある はい

開始位置から到達できる

屋根ありでも legal_pose/3 と supported/2 は目標の姿勢に成功する。しかし、開始位置から訪問した628姿勢に目標は現れない。屋根を外すと656姿勢がつながり、目標までの下移動19回が見つかる。ここでは、盤面上の条件と、操作による到達を別々に尋ねている。

04

探索を閉じることと、状態を同じとみなすこと

開始姿勢から一手で届く姿勢を足す。次に、その姿勢から一手で届く姿勢を足す。もう新しい姿勢が増えなくなるまで続ける。この「届く範囲を増やす」操作を、今回のコードではキューと訪問済み集合を持つ幅優先探索で実装した。

Prologが自動で幅優先に探すわけではない。一歩の候補を作る関係と、どの順にその候補を調べるかは、分けて書いている。

デモ盤面で実際に発見した層同じ姿勢は一度だけ訪問

この範囲には、614の姿勢があった。そのうち下へ進めず、四セルが見える盤面に収まるものを固定候補にする。同じ四マスを占める表示上の重複をまとめると、Qに並ぶ34候補になる。

幅優先探索が最小化するのは、五種類の操作をそれぞれ一単位と数えた手数。経過時間や人間にとっての難しさは、この費用には含まれていない。

この増やし方を「最小不動点」と呼ぶ

姿勢pから操作aで姿勢qへ進めることを EB(p,a,q) と書く。Bは固定した盤面だ。集合Xから一歩で届く姿勢を postB(X) とする。

FB(X) = {p0} ∪ postB(X)

開始姿勢を含み、一歩進んでも外へ出ない集合のうち、最も小さいものが到達集合Rになる。

R = μX. FB(X)

μは「その条件を満たす最小の不動点を取る」という記号。ここでは、Fを適用しても増えなくなった集合を指す。上の表示はR0={p0}から始め、Rd+1=Rd∪postB(Rd)と増やした層を見せている。

一種類について、原点Xは−3〜9の13通り、Yは−4〜19の24通り、回転は4通り。高々 13 × 24 × 4 = 1248姿勢で、一歩の操作は最大五つ。実際には壁や衝突でさらに減る。この有限領域と訪問済み管理が、今回の探索の終了を支える。

これはその範囲での探索の説明であり、ホールド、次のピース、固定時間、無限のゲーム全体の戦略まで解いたという意味ではない。

同じ四マスなら、同じ状態にまとめてよい？

水平なIは、二つの姿勢で同じ四マスを占める。ところが、両方を右回転させると、次に占める四マスは違う。いま同じに見えることだけでは、次の操作も同じだとは言えない。

同じ見た目 / 違う原点と回転番号

丸印は局所座標(0,0)に対応する原点のマス。ピースの左端や回転中心そのものとは限らない。ここは盤面の一部、X=3〜8・Y=9〜15を拡大している。

だから、探索中のキーには種類・回転番号・原点を全部残す。到達を調べ終わった後で、表示する固定候補だけを四セルの集合でまとめ、手順を一つ残している。

p ∼ q　⇔　C(p) = C(q)

C(p)は姿勢pが占めるセル集合。この同値関係で表示をまとめることと、この同値関係で探索の状態をまとめても操作が保存されることは別の主張だ。後者を確かめずに、前者の都合で情報を消してはいけない。

05

時計を進めること、残る情報を選ぶこと

Qの探索には、重力も固定までの残り時間も入っていない。通常プレイでは、それらが進む。探索で見つかる操作列が、時計の進むゲームでも間に合うかは、もう一つの問いになる。

ネイティブ版でEnterを押して手順を再生するときも、重力と固定待ちを止めている。途中へ瞬間移動するのではなく同じ一歩を通すが、実時間の成立まで証明する再生ではない。

キー・時刻外の世界で起きる
→
SWI-Prologact / tick / 関係・探索 / 描画指示 / ループ
→
薄いCの橋渡しraylibへ矩形・文字などを渡す
→
Windowsの画面実際に描かれる

Prologが入口なので、ゲームの規則、入力の解釈、探索、画面の組み立ては .pl にある。現在の外部述語で足りる変更なら、Cを再ビルドせずゲームを起動し直せる。一方、画像・音声・3Dを足すなら、関数に加えて外部資源の読み込み・識別・解放を扱う橋渡しが必要で、まだ実装していない。

別の答えが出ることと、過去を復元できること

下の二つの盤面を消してみよう。一行埋まった盤面も、二行埋まった盤面も、残る盤面は同じ空になる。

行消去で、盤面から消える区別

A：10セル

消えた行数：まだ消していない

B：20セル

消えた行数：まだ消していない

「消す前へ戻す」は保存済みの表示を切り替える操作。消去後の盤面から、実際の履歴を計算し直しているわけではない。

A ≠ B　でも　clearBoard(A) = clearBoard(B) = []

盤面だけを見る行消去は単射ではない。異なる入力が同じ出力になるため、空の盤面だけでは、どちらが過去だったのか一つに決まらない。消えた行数も保存すれば、この二つは区別できる。スコアや行数を含むゲーム状態全体まで同じだという話ではない。

関係を逆向きに尋ねれば「あり得る以前の盤面」を複数求められるかもしれない。でも、それだけでは実際に起きた歴史が一つに戻るわけではない。どの情報を観測し、保存したかが問題になる。

このプログラム全体が、逆向きに動くわけではない

piece_cells/5 の一部の引数は未定にできるが、盤面の生成、時刻、乱数、描画まで同じように逆向きに扱えるわけではない。

  • supported/2 は、決まった盤面・姿勢で「下移動が失敗するか」を \+ で調べる。未定の変数に対する一般的な否定として使わない。
  • 回転は壁蹴り候補の最初の成功を once/1 で選ぶ。探索だけに別の壁蹴りを自由に選ばせない。今回の簡易壁蹴りはSRS準拠ではない。
  • 移動の is/2、バッグ、スコア、時刻、キー入力、描画には方向がある。外へ描いた画面や起きた入力は、バックトラッキングで巻き戻るものとして扱わない。
  • CLP(FD)を使う部分も、整数の有限領域を早く置くという呼び出し条件に限る。エンジン全体の単調性や、あらゆる算術項での関係性を主張しない。
06

Prologを選んで、何を調べられるようになったか

この一作で、四マスを埋める条件、操作がつながる範囲、時計が進む状態、観測に残る情報を、実際に動く同じゲームから取り出せた。

Prologを中心に置くと、「入力から答えを一つ作る」だけでなく、何を決め、何を未定にし、どの条件で結ぶかをコードの入口にできる。その代わり、条件を記述する部分と、解を列挙する部分、探索の順序、外の世界への作用を、丁寧に見分ける必要がある。Qで動いたのは、その区別を具体的に試せる、小さいが本物の場だった。

Haskellの関数や型を知っているなら、値を一つ作る視点に、条件を満たす項の組を探す視点を並べてみるとよい。関係や探索はHaskellでも表せる。今回の成果は、言語ごとに役割を固定することより、どんな記述を共有し、どの情報を残す必要があるかを、実装と反例から比べられることにある。

一本の手順の先には、「どの場合にも応じる」がある

いまの探索が求めるのは、現在の一個について成功する操作列があるか、という答えだ。次に何が来るか分からない状況まで考えるなら、問いの形が変わる。

いま一手を選ぶ。次にどのピースが来ても、
その後に、また適切な手を選べるだろうか。
∃a0　∀k1　∃a1　…

「ある手を選べる」と「どの場合にも、その後の手を選べる」では、量化の順序が違う。これは将来の研究候補で、現在の34候補が解いている戦略ではない。時間も確率も、fp-gameとの統合も、ここから別に考えられる。

この場面を、自分の言葉で説明してみる

図を思い浮かべて、まず自分の言葉で説明してみよう。必要なところだけ答えを開ける。

Oの答えが四つある。四つの違う置き方が見える？

この例では同じ四マスで、回転番号0〜3が残っている。物理的なセル集合が一つでも、姿勢の表現は複数あり得る。

空洞に収まり、床にも支えられるのに、Qの答えに出ないのは？

形と衝突の条件は満たすが、開始位置から共有する操作をつないで入る経路がないため。静的な条件だけでは到達の答えにならない。

Iの見た目が同じなら、探索で片方を消してよい？

この二つは右回転後に違うセルを占める。見た目で同じとみなすとき、その同一視が次の操作も保存するかを確かめる必要がある。今回の探索は、回転と原点を残した。

ある着地点への最短手順が見つかった。これだけで、通常プレイでも間に合うと分かる？

現在の探索からは判断できない。最短は一操作一単位の手数で、時計や入力の繰り返しを含まない。

行消去後が空なら、消す前も一つに決まる？

決まらない。10セルと20セルの二つの盤面が同じ空の盤面になる。盤面以外に何を記録したかが、区別できる過去を変える。

このページの記録と、確かめられる出所

表示する座標、答え、操作列、消去後の盤面、発見した層は、既存のゲーム述語を呼んで書き出した。34候補の全手順を再生し、逆問い合わせの具体的な答え、屋根の有無、Iの右回転後の座標を、生成時に検査する。JavaScriptは保存されたデータの選択と描画だけを担当する。

614姿勢・34候補・約22msは、2026年10月26日にこのPCのデモで観測した例。盤面や環境が変わった場合の性能保証ではない。2026年10月26日、このゲームを実際に遊んだユーザー本人が通常プレイとQでの探索の動作を確認した。検査の詳細と範囲は、プロジェクトのVALIDATION.ja.mdに記録している。

ソースの指紋と、再生成方法

プロジェクト内で scripts/build-guide.ps1 を実行すると、ネイティブのPrologから再度書き出して、この単独HTMLを作り直す。閲覧自体にはProlog、Python、サーバー、ネット接続は不要。

ゲームの規則は src/tetromino.pl、探索は src/reachability.pl、時間を伴う更新は src/game.pl、入口は src/main.pl。書き出しは scripts/export-guide.pl、HTMLの組み立ては scripts/build-guide.py にある。
