# 盤面の関係を調べ、同じ規則でピースを動かす

`tetromino.pl` に一つのピースが占める四つのマスを定めています。通常の衝突判定でも、「この四つの空きマスに合うピースは何か」という問い合わせでも、その関係を使います。到達探索は通常プレイと同じ `move_pose/4` を呼び、操作を一つずつ進めます。

## 別のゲームを Prolog で作るとき

起動するプログラムは SWI-Prolog です。`src/main.pl` がキーや時刻を読み、Prolog の規則でゲームを進め、`src/view.pl` が矩形や文字の描画を組み立てます。C の DLL は、現在必要な raylib のウィンドウ・入力・時刻・描画操作だけを外部述語として公開します。C 側からテトリスの状態を動かす形にはしていません。

例えば盤面の規則、敵の行動、探索、画面の配置を `.pl` ファイルで変更した場合、ゲームを起動し直すと変更が読み込まれます。現在の外部述語で足りる限り、C を再ビルドする必要はありません。この境界を保てば、Prolog を入口にしたまま別の規則や小さな 2D ゲームを試せます。ただし、この一作でゲーム一般の作りやすさを検証したわけではありません。

画像、音声、3D 表示を加える場合、現在の橋渡しには必要な raylib 関数がありません。関数を追加するだけでなく、テクスチャや音源などをいつ読み込み、どの識別子で Prolog に渡し、誰がいつ解放するかを定める必要があります。Prolog のメモリー管理だけで外部資源の寿命が自動的に決まるとは扱えません。これらの資源管理を含む外部述語は、まだ実装・検証していません。

既存の SWI-Prolog/raylib の小さな PoC も調べましたが、この試作では公式の固定バージョンに対して小さな橋渡しを自作しています。確認した raylib 公式のバインディング一覧には Prolog がありませんでした。別の実装が存在しないことの証明ではありません。調べた範囲と出所は [SOURCES](SOURCES.md) にあります。

## 表現と入力条件

盤面は `cell(X,Y,Kind)` のリストです。左上を `(0,0)`、右下を `(9,19)` とします。通常の盤面では座標が重複せず、すべてのセルと種類が決まっています。`game_valid/1` で通常ゲームの状態の一部を点検できます。

ピースの姿勢は `pose(Kind,Rotation,X,Y)` です。`Rotation` は 0～3。J/L/S/T/Z は 3×3、I は 4×4 の座標枠で回転し、O は同じ四つの座標を四つの回転番号で表します。

| 述語 | 入力・出力と範囲 |
| --- | --- |
| `piece_cells(?Kind,?R,?X,?Y,?Cells)` | 形と四セルの関係。R は 0～3、X は -3～9、Y は -4～19 に制約する。形の事実は有限。座標を未定のまま制約を返せる |
| `legal_pose(+Board,?Pose,?Cells)` | 決まった盤面に対して、セルが盤面内で重ならない制約を追加する。移動中は Y=-4～-1 の隠れた行を許す。座標の列挙はしない |
| `enumerate_pose(+Board,?Pose,?Cells)` | `legal_pose/3` に続いて有限な R/X/Y を `labeling/2` で列挙する |
| `cover_cells(+FourCells,?Pose)` | 順不同・重複なし・すべて整数座標の四セルを渡す。盤面に見える座標の範囲で、種類・回転・位置をすべて求める。四セルの順列 24 通りと同じ `piece_cells/5` を使う |
| `move_pose(+Board,+Pose,+Action,-Next)` | 決まった姿勢に、left/right/down/cw/ccw の一操作を与える。成功する結果は最大一つ。失敗は操作不可を表す |
| `supported(+Board,+Pose)` | 置けて、下への一歩が失敗する姿勢かを調べる。姿勢を生成する用途には使わない |
| `lock_board(+Board,+Pose,-After,-Lines,-Rows)` | 支えられた姿勢を固定して行を消す。四セルすべてが見える行にあることが必要 |
| `reachable_locks(+Board,+Start,-Candidates,-Info)` | 現在の決まった姿勢から、時間なしで到達できる固定位置と操作列を列挙する |
| `replay_path(+Board,+Start,+Actions,-End)` | 同じ `move_pose/4` で操作列を再実行する。途中で不可能な一歩があれば失敗する |

`legal_pose/3` は、セル座標がすべて決まった場合には通常の整数セルの照合を使い、未定なら `#\=` と `#\/` の有限領域制約で衝突を除きます。両方の呼び方が一致することを小さな盤面の独立した列挙でテストしています。盤面そのものを未定にして生成する述語ではありません。

`cover_cells/2` の回転した T の例は `pose(t,1,4,8)` だけを返します。一方、水平 I の同じセル集合には回転 0 と 2 の二つの原点表現があり、O には四つの回転番号が残ります。「物理的な形が一つ」と「姿勢の表現が一つ」は異なります。

## 移動と回転

横移動は一マス、下移動は一行です。回転は回転番号を ±1 してから、次の原点補正をこの順で試し、最初に衝突しないものに決めます。

```text
(0,0), (-1,0), (1,0), (-2,0), (2,0),
(0,-1), (-1,-1), (1,-1), (0,-2)
```

この試作独自の簡易壁蹴りです。ピースごとの SRS 表は実装していません。探索でも任意の壁蹴りを自由に選ばせず、同じ順序の最初の成功だけを使います。

ソフトドロップは一行につき 1 点、ハードドロップは一行につき 2 点です。一度に 1/2/3/4 行消すと、100/300/500/800 × 消す前のレベルを加えます。累計 10 行ごとにレベルが上がります。連続消し、Back-to-back、T-spin、パーフェクトクリア加点はありません。

横移動は最初に一マス、その後 160 ms 待って約 45 ms ごとに繰り返します。ソフトドロップは約 35 ms ごと。重力の間隔はレベル 1 で 750 ms、以後 `max(55 ms, 750 ms × 0.82^(level-1))` です。フレームの時間差は 50 ms に制限するため、大きく処理が遅れたときには実時間よりゲームが遅くなります。

着地後の固定待ちは 500 ms です。着地中の成功した移動・回転でリセットしますが、一個につき最大 15 回です。失敗した操作ではリセットしません。隠れた行にセルが残る固定、または次のスポーン位置に既存セルがある場合はゲームオーバーです。

バッグはローカルの明示的な 32 bit LCG から作ります。シードと操作・時間差をそろえれば再現できます。各バッグには七種類が一回ずつ入ります。乱数の暗号学的品質や厳密な一様分布は目的にしていません。

## 探索の範囲

探索は left/right/down/cw/ccw で到達できる姿勢を幅優先で調べ、姿勢全体を訪問済み集合のキーにします。回転番号を残したまま探索を閉じた後、同じ四セルを占める固定位置をまとめ、一つの操作列を残します。回転番号を早期に消しても遷移が保存される、という仮定は置いていません。

探索する姿勢の原点は X=-3～9、Y=-4～19、回転は 0～3。種類は開始時の一種類に固定され、各辺の分岐は最大五つです。この入力条件では探索空間が有限なので、訪問済み管理によって終了します。

候補の手順は、各操作を同じ一単位として数えた最短手順です。最短時間や人間にとっての簡単さを最適化しません。表示順は消える行数が多い順、その後に手順の長さなどでそろえています。「最良の次手」という評価ではありません。

ホールド、次のピース、重力、キー繰り返し、固定待ち時間はこのグラフに入りません。通常プレイの `tick/3` がそれらの時間を進めます。Enter による手順再生は同じ移動述語を通しますが、重力と固定時間を停止しており、最後にハードドロップで固定します。

## 逆向きに使わない処理

形とセル位置の一部は関係として問い合わせられますが、プログラム全体を逆向きに実行できるわけではありません。

- `supported/2` の下移動の否定、決まったセルでの占有確認、回転の最初の成功を選ぶ `once/1` は入力の向きと順序を前提にします。
- 行消去、スコア更新、バッグ生成、時刻やキー入力、描画は方向のある処理です。
- CLPFD を使う範囲でも、先に整数の有限領域を設定する契約に限ります。SWI-Prolog 全体の単調性や任意の算術項での関係性を主張していません。

`projection_witness/3` は、一番下だけが全部埋まった 10 セルの盤面と、下二行が埋まった 20 セルの盤面が、どちらも空の盤面に消える例です。盤面だけから前を一意に復元できないことを示します。行数やスコアを含めたゲーム状態全体が等しい、という主張ではありません。
