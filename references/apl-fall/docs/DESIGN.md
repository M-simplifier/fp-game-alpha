# APLで盤面と配置の関係を記述する

この試作では、空洞のある盤面を渡すと、各ピースがどの向き・位置に収まるかを一つの配列として返す。その配列をプレイ中の衝突判定、ゴースト、落下、配置の観察で共用する。ゲームの規則と描画指示は実際のAPL処理系が実行し、Raylibを呼ぶホストは入力・時計・汎用の図形だけを扱う。

本書は実装前に選んだ数学的な表現を、動作するコードと照合して説明するものだ。機能・操作方法・測定結果はREADMEと検証記録を参照する。既存Haskell基盤への統合は今回の前提にしない。

## 配置からセルを見る、セルから配置を見る

盤面のセル集合を Z、ピースの種類・向き・基準位置で指定した配置の集合を C とする。配置 c の占有セル集合を K(c) と書く。盤外には専用の番兵セルを置き、そのセルは常に塞がっているとする。

たとえば横向きのIを左端に置いた配置は、同じ行の四セルに対応する。この対応を各配置について並べると、配置とセルの関係 M ができる。

    M[c,z] = 1  ⇔  z ∈ K(c)

同じ M から二つの計算が導ける。

    D(X) = ⋃ {K(c) | c ∈ X}
    E(F) = {c | K(c) ⊆ F}

D は選んだ配置集合 X が覆うセルを求める。E は空きセル集合 F に完全に収まる配置を求める。次の同値が成り立つ。

    D(X) ⊆ F  ⇔  X ⊆ E(F)

左辺は「選んだ全配置が覆うセルはすべて空いている」、右辺は「選んだ全配置が配置可能である」であり、同じ条件を言い直している。この全称・存在の対応は順序に関する随伴 D ⊣ E を与える。ここでの数学的主張はこの定義から導いたもので、新しい定理やAPL専有の性質とは主張しない。

占有配列 O を使えば、配置可能性は Boolean の内積で表せる。

    possible = ~ (M ∨.∧ O)

実装では大量のゼロを持つ M を保存する必要はない。各配置に属する四つのセル番号を [配置, 占有セル] の整数行列 I に保持すれば、同じ計算を gather と縮約で実行できる。

    possible ← ∧/ (0 = extendedBoard[I])

これは一つずつ衝突判定を呼んだ結果を後から配列にする設計ではない。配置軸と占有セル軸を先に作り、配列演算で配置全体を計算する。実際の `apl/core.apl` の `Feasible` は次の二行を実行する。

```apl
extended←(,board),1
field←∧/0=extended[Foot[type;;]]
```

盤面を一列に並べ、末尾へ盤外用の1を加えている。盤外を含む配置は、四セルの少なくとも一つがこの1を読み取るため不合法になる。

## 軸にはゲーム上の意味がある

主要な配列の軸を固定する。

| 対象 | 軸・値 |
| --- | --- |
| 固定済み盤面 | [行, 列]、0は空き、1..7は色／種類 |
| 形 | [種類, 向き] ごとの小さなBoolean行列 |
| 配置の占有セル | [種類, 向き, 基準行, 基準列, 四セル] |
| 配置可能性 | [向き, 基準行, 基準列]、Boolean |
| 到達可能性 | 同じ配置軸、Boolean |
| 表示する四角形 | [図形, 属性] |

表は意味上の軸を示す。実装は向き・基準行・基準列を一つの配置番号へ畳み、`Foot` を7×1300×4、`Field` を1300要素で保持する。`Poses` が配置番号と三つの座標の対応を持つ。一種類につき4方向×25基準行×13基準列であり、表示するときは325要素ずつ四方向へ分ける。次元を畳んでも、どの軸を縮約しているかは変わらない。

位置の軸を取れば現在姿勢の衝突判定になる。列と向きを固定すれば縦方向の落下経路になる。向きを固定すれば配置可能な場所の二次元図になる。表示のためだけに作る配列ではなく、同じ値を規則と観察が使う。

小行列の時計回り回転は `⌽⍉` で表せる。3×3のJ/L/S/T/Z、4×4のI、2×2のOから四つの向きを生成し、占有セルの座標へ変換する。四回回すと元の形に戻る。Oのような対称形は異なる向き番号で同じセルを占めるため、姿勢番号の一致と幾何学的な形の一致を混同しない。

盤面は22行×10列、上2行を隠れた出現領域とし、表示は20行とする。基準位置には負の値も認める。小行列の余白が盤外に出ることと、占有セルが盤外に出ることを区別する。初期化時に全候補の索引を用意し、盤外セルを番兵へ写す。

この実装では盤面寸法・候補範囲・番兵番号220を固定している。上の定式化は他の寸法にも適用できるが、現コードを寸法だけ差し替えられる汎用ライブラリとしては提供していない。

## 落下は、最も低い合法位置を選ぶ操作ではない

上から下へ同じ列の配置可能性が `1 1 0 1 1` だったとする。最後の二つは屋根の下の空洞に対応する。最大の合法行を選ぶと、ピースは屋根をすり抜ける。

現在位置から下の列を v とすると、途中も含めて通れる位置は `∧\v` で求められる。

    v          = 1 1 0 1 1
    ∧\v        = 1 1 0 0 0
    dropDistance = (+/∧\v) - 1

末尾に不合法の番兵を置き、現在位置が合法であることを前提にする。この同じ計算をゴーストとハードドロップに使う。単純な列の最大高さでは凹凸・空洞・ピースの形を失うため、配置可能性の場を経由する。

## 収まる配置と、操作で到達できる配置を区別する

配置可能性だけでは、隠れた空洞へ入れるとは限らない。左・右・下・時計回り・反時計回りの各操作について、配置から次の配置への写像を作る。回転は優先順つきの簡易壁蹴りを使う。選ぶ候補は最初に合法となった一つであり、候補すべてへ同時に移動できる規則にはしない。標準SRSへの準拠は主張しない。

ゲームで実行する操作と、探索が使う操作の意味を揃える。各操作の移動先を配置軸上の整数配列にすれば、到達集合 R は次の反復で広がる。

    R₀ = {現在配置}
    Rₙ₊₁ = Rₙ ∪ ⋃ₐ Tₐ(Rₙ)

盤面を固定した有限集合上で、これは単調かつ増加する。変化がなくなった時点が最小不動点になる。密な隣接行列を使う必要はなく、移動先索引へのBoolean scatterで表せる。再生に必要な場合は、各配置へ最初に着いた操作と直前の配置を配列で記録する。

観察モードでは時計を止め、配置可能な点と到達可能な点、下に進めない着地点を見分けられるようにする。この探索は時間制限・自動落下・ロック待ちを含む攻略可能性の証明ではない。

## 行消去は、残す行を選び直す操作になる

盤面 B の満杯行を `full ← ∧/ B≠0` で求める。残す行を第一軸で圧縮し、消えた行数だけ上にゼロ行を加える。

    keep ← ~full
    cleared ← ((+/full),width)⍴0
    result ← cleared ⍪ keep⌿B

残す行の順序を変えないため、各ブロックを個別に落とす処理は要らない。0始まりの元の行 i は、消えた行の総数を d とすると、残る場合に `d + (+\keep)[i] - 1` 行へ移る。これは削除を含む座標の作り直しである。

消えた行の色は結果から復元できない。消去演出や履歴で必要なら、消去前に行マスクと元の行を結果とは別に残す。配列を短く書くことによって情報消失を隠さない。

## ゲーム全体まで単調とは限らない

固定した形に対し、盤面へブロックを追加すると配置可能な場所は増えない。これはEの性質から分かる。一方、最後の一セルを埋めると行が消え、空き場所が増える。したがって「衝突の場は単調」という性質を、ロック・行消去を含むゲーム全体へそのまま持ち込めない。

配列の軸を揃えることは、独立性や操作の交換可能性も保証しない。右へ動かしてから回す結果と、回してから右へ動かす結果は、壁の近くで変わりうる。入力順序と時間は明示して残す。

## 全体を計算する範囲を選ぶ

このゲームで配列に並べるのは、一つの固定された盤面に対する配置の候補である。22×10セルの占有盤面だけでも組合せは2の220乗ある。盤面・次のピース・時計を含む全ゲーム状態を列挙しているのではない。

同じ区別は最適化にも効く。配置とセルの関係 M は形と盤面寸法で決まり、ブロックが積まれるたびに作り直す必要がない。変わるのは盤面の値と、そこから得る配置可能性である。形の対応関係を先に保存し、盤面だけを差し替えると、描画・衝突・観察が同じ幾何を参照できる。

ただし、一括計算は常に速いとは限らない。一点の衝突だけを知りたいなら四セルを調べれば足りる。配置の場を作る利点は、ゴーストや観察など複数の問いへ同じ結果を使えることにある。実行時間は処理系と再利用回数を含めて測る必要がある。

Haskellで状態更新を型と関数の関係として記述することも、Prologで合法配置を関係として問うことも、この配列モデルと両立する。今回APLで前面に出すのは、候補集合を値として持ち、その軸を選び、演算を変えて問いを作る操作である。言語ごとに担当する仕事を固定する結論にはしない。

ECSとの比較で得られたのは、主体の一覧だけでなく、配置や操作の候補にも軸を与えられるという検討材料である。異種の部品、可変の関係、大量の疎な主体をどう表すかは、この小さな密な盤面だけでは決まらない。

## 完成を判断する証拠

- APL処理系が規則・更新・描画指示を実行し、Raylibの実ウィンドウで通常プレイできる。
- 配置可能性の一括計算を、別の素朴なセル列挙による判定と照合する。両方が同じ関数を呼ぶテストにしない。
- 盤外の余白、屋根の下の空洞、両端の壁、隠れた出現領域、複数行の同時消去を反例として含める。
- 四回回転、四セル保存、色に依存しない衝突、占有追加による配置可能性の縮小、行消去の冪等性・残存行の順序・セル数保存を調べる。
- 探索は現在の合法姿勢から始まり、実プレイと同じ操作を使う。時計を止めた探索であることを表示する。
- ランタイムと依存物を同梱し、元の開発ディレクトリに依存しない起動を検証する。
- 実装したこと、実行確認したこと、形式的に導いたこと、プレイヤーの楽しさを区別して報告する。

## 既存の知見との関係

Iversonの論文は、配列・名前・演算子で細部を従属させ、同じ演算の組合せから別の問いを発見できる記法を論じる。この試作では、縮約・走査・圧縮が、衝突・経路・行消去をどう関連づけるかを実行可能な形で確かめる。[Kenneth E. Iverson, Notation as a Tool of Thought, CACM 1980, §§1.2–1.3](https://www.sigapl.org/Articles/Notation%20as%20a%20Tool%20of%20Thought_a1979-iverson.pdf)。

形を空き領域へ当てはめるEは、固定した形については数理形態学の収縮（erosion）と同じ包含条件を持つ。配置の種類・向きも軸として含めた点が、このゲームで使う表現である。APLがこの数学を独占するわけではない。配列を主要な対象として扱うと、これらの計算を同じ記法とデータから直接組み立てられることを試す。

この段階で一般ゲームエンジンやECSの完全な一般化が得られたとは言わない。可変個数の主体、時間を持つ関係、連続空間、大規模な疎配列へどこまで広がるかは別の実装で確かめる必要がある。
