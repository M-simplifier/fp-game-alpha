# 実際のAPLと実ウィンドウで確認したこと

`Test.cmd`は、APLが返した判定を別のセル列挙実装と比べた後、キー入力記録を実ウィンドウへ渡します。前者は配列の計算と規則の照合、後者は入力から画面までがつながることの確認です。人が遊んだ時の操作感や楽しさは、これらの件数からは判断しません。

## 再実行

準備済みランタイムとPython 3.10以降があるWindowsで、プロジェクトの`Test.cmd`を開きます。個別には次を実行できます。

```powershell
python .\tests\oracle.py
python .\tests\gui_smoke.py
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\test-game.ps1
```

結果、入力記録、生のAPL出力、PNGは`.scratch/evidence/`に入ります。テストは言語エラーを標準出力からも検出します。GNU APLが言語エラー後にも終了コード0を返す場合があるため、終了コードだけで合格にはしません。

## 独立したセル列挙との照合

`tests/oracle.py`は小行列やAPLの`Foot`を使いません。四つの整数座標のリストを持ち、`(r,c)→(c,size−1−r)`で回します。各候補について四セルを一つずつ調べ、壁蹴りは優先順に一つずつ試し、到達可能性は通常のキュー探索で求めます。Pythonはテストだけで実行され、ゲーム規則の実行時には参加しません。

空、全占有、閉じた空洞、盤面を横断する屋根、隠れた出現領域の障害、段差、四密度の固定種盤面の計10盤面について、7種類すべてを照合します。

| 対象 | 確認した数と条件 |
| --- | --- |
| 配置可能性 | 91,000候補。負の基準位置・両端・隠れた行・盤外番兵を含む全候補 |
| 操作の移動先 | 455,000件。五操作と回転候補の優先順を全候補で比較 |
| ゴースト／落下 | 15,953開始点。別実装で一行ずつ下降した距離と一致 |
| 到達可能性 | 72,800 Boolean値。合法な出現姿勢からキュー探索と一致 |
| 保存した経路 | 21,908の親子辺が合法。見本の全36着地点へ実際の`MoveAction`で再生 |
| 回転とセル | 7種類×4向きの座標と四セルを比較。実APLと独立側の両方で四回回転後の一致も確認 |
| 行消去 | 14盤面。全消去、複数・非連続・先頭行を含み、残る行の順序、冪等性、セル数を比較 |
| その他の性質 | 色を変えても判定が同じ、占有追加で合法な配置が増えない |
| 乱数 | 20袋の全140個と最終種が独立側と一致。各袋が7種類を一度ずつ含む |
| 決定的な再生 | 固定種・900刻み。盤面・姿勢・キュー・種・得点等の全結果が一致 |

屋根の反例では、横Iは基準行8で止まります。基準行15でも形は収まりますが、下への経路上に屋根があるため落下先にはなりません。余白の反例では、横Iの基準行−1、縦Iの基準列−2も、占有セルが盤内なら合法です。

## ゲームの時間と操作

通常の出現位置から、保持を続けた横移動が1・10・11・14刻み目に列2・2・1・0になること、下の12刻みで4セル進み4点になることを確認します。既に離された左右・下キーの押下縁、相反する左右、保持の連続使用禁止、固定後の再使用、交換も検査します。

ポーズ中の90刻みで盤面・姿勢・ゲーム時刻が進まないこと、再開、29刻み目には固定せず30刻み目に固定することを確認します。さらに、15セルを超えて下降した後も猶予の予算が0のまま残り、接地した横移動で時計が戻ること、15回の上限を超えた次の成功操作では時計が戻らないことを検査します。隠れた行による終了と、再開始時の初期化も含めています。

## 実ウィンドウの入力記録

`tests/gui_smoke.py`は、ホストへ固定時間とキーの押下・解放だけを渡します。判定と更新は通常どおりAPLが行います。

| 入力記録 | 実行結果 |
| --- | --- |
| 初期画面 | 最初からOの一部が見える。実PNGの指定セル色も一致 |
| 観察へ入った最初の描画 | 2フレーム目から盤面と四つの図を両方保持。実PNGの屋根セル色も一致 |
| Tの観察図 | 同じ固定盤面で、四つの向きが異なる図を表示 |
| 移動・両回転・速い落下・保持 | 2ピース固定、70点、保持L。130描画後のゲーム時刻108刻み |
| ポーズ | 90描画後もゲーム時刻74刻みで停止し、ポーズ表示 |
| 着地点選択→経路再生→通常へ戻る→固定 | 右下の穴で2行消去、1ピース、300点 |
| 同じ列に積み続ける | 12ピースで終了表示 |
| 終了後のR | 得点・行・固定数・保持を初期化して通常プレイへ |

これらはホストへ注入したキーと画面の接続を確認したものです。人の操作感そのものの記録ではありません。

別に、親担当が2026-10-26にOSへキーを送るComputer Useで実ウィンドウを操作し、Rでの再開始、Tの左移動と上キー回転、Pのポーズ、Sの空洞表示、Enterによる17操作の屋根上への再生、Tabでの通常復帰、Spaceによる得点0→6の固定、CでのO保持・Lへの交換を実画面で確認しました。ウィンドウの閉じるボタンでも終了コード0・protocol okでした。これはホスト内部の入力記録とは別のOS経由の確認ですが、人が指で打鍵した記録や、遊び心地の評価とは区別します。

このOS確認では、同じポーリング間隔の中で押して離す短い入力をホストが落とす問題を実際に発見しました。Raylibのキー押下キューを読み取るよう修正し、上記の操作を確認し直しています。基盤側には、実ウィンドウへRと左の押下・解放を送り、held=0でもpressed=1を一回だけ受け取る検査を追加しています。

終了画面の個別PNGは、この公開選別版には含めません。通常画面と観察画面は
[操作図つきの解説](../../../site/studies/array-fall.html)に埋め込んでいます。
上記の終了・再開始の確認は、`tests/gui_smoke.py`による記録です。

## このホストでの測定

GNU APL 2.0のWindows実行ファイル（自己申告SVN 3506M）で、空洞盤面・Tについて`⎕AI[2]`の差分を測りました。1300姿勢の判定場を200回、五操作の移動先配列を50回作り、代表的な一実行では平均約0.26msと約11.1msでした。プロセス起動、描画、探索の時間はこの二値に含みません。両配列は盤面・種類が変わる時だけ作ります。

実ウィンドウの130描画の入力記録は、描画目標120Hz・固定ゲーム時間1/60秒という検査条件で、起動終了を含め約1.6秒でした。この値は通常プレイの毎秒描画数、別PCでの速度、最悪時間の保証ではありません。測定値は再実行ごとに`.scratch/evidence/oracle-summary.json`と`gui-summary.json`へ出力します。

ホストのピクセル検査、入力の縁、停止したAPLからのウィンドウ終了、子プロセス解放などは[PLATFORM.md](PLATFORM.md#observed-verification-and-limits)にあります。形式的な包含関係の導出は[DESIGN.md](DESIGN.md)に分けています。

## ローカルZIPを展開して確認

最後に結合した`Test.cmd`が終了コード0で合格しました。`tools/package.ps1`で作った`dist/apl-tetris-windows-local.zip`を別の検査フォルダへ展開し、55ファイルのSHA-256を同梱manifestと照合しています。その展開先だけを使い、PATHを`Windows\System32`に制限した状態で、APL配列の描画例と`tools/run.ps1`からの実ゲーム起動が両方とも終了コード0でした。実ゲームの展開先PNGも通常画面として確認しました。

ZIP全体のSHA-256は同じ出力先の`apl-tetris-windows-local.zip.sha256`にあります。これは準備済みのWindowsローカル用フォルダが、元の開発場所や開発ツールのPATHに頼らず起動した証拠です。別PCでの動作や、公開配布に必要なソース対応の確認は含みません。
