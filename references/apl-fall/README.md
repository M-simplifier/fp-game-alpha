# ARRAY / FALL — APLの配列で落ちものゲームを捉える

盤面を渡すと、7種類のピースが各向き・各位置に収まるかを配列で求めます。
その同じ配列を衝突判定、ゴースト、落下、操作で届く配置の観察に使います。
GNU APLがゲーム規則・更新・描画指示を実行し、小さなCホストがraylibの画面、
入力、時計を扱います。独立した言語実験であり、alphaへの統合実装ではありません。

[操作図つきの解説](https://m-simplifier.github.io/fp-game-alpha/studies/array-fall.html) ·
[配列の設計](docs/DESIGN.md) · [正確な規則](docs/IMPLEMENTATION.md) ·
[検証の条件と限界](docs/VALIDATION.md)

検査、再現手順を含みます。実行ファイル、第三者の処理系、配布ZIPは含みません。

## このフォルダから実行する

Windows x64、PowerShell、Visual Studio C++ x64ビルドツール、Windows SDKを用意し、
このフォルダで次を実行します。初回のみ、固定した公式配布物を取得します。
システムへのインストールやPATHの恒久変更は行いません。

```powershell
./tools/setup.ps1
./Play.cmd
./Demo.cmd
```

`setup.ps1`はSHA-256を照合して`.runtime`に展開し、ホストを作ります。
`Play.cmd`は通常プレイ、`Demo.cmd`は屋根のある空洞と到達できる穴を示します。
左右で移動、X/Zで回転、Spaceで固定、Cで保持、Pで停止、Tabで観察へ切り替えます。
観察中はA/Dで着地点を選び、Enterで操作列をたどります。

独立した検査にはPython 3.10以降が必要です。

```powershell
python tests/oracle.py
./Test.cmd
```

`oracle.py`は四セルを逐一調べる別実装とAPLの一括計算を照合します。
既存の準備済み依存物を読む場合だけ、`ARRAY_FALL_RUNTIME`にその`.runtime`
フォルダを設定できます。ゲームソースはこの公開版を読みます。
`Test.cmd`の画面検査やPlay/Demoは通常どおりこのフォルダの`.runtime`を使います。

## 読み比べるときに残す違い

`Foot[7;1300;4]`は一つの固定盤面に対する有限の配置候補です。ゲームの全状態や
将来の盤面を列挙しているわけではありません。盤面は22行×10列、上2行は非表示。
回転は優先順つきの簡易kickで、SRSではありません。

観察モードでは時計を止めます。「形が収まる」「現在位置から操作で届く」を
分けて表示しますが、通常プレイの重力・入力反復・固定猶予を含む攻略を解きません。
配列の使い方から、一般のECSや疎な可変個数の主体にまで有効だとは結論しません。
