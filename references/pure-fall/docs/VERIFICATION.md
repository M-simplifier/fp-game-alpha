# PURE / FALL を確認した範囲

2026-10-26、Windows x64で実行しました。ウィンドウを開く処理、実際のキー入力、
画面を開かないルール検査を分けて記録しています。テストが通ったことと、
人が遊んで楽しいと判断したことは同じ証拠として扱いません。

## ビルドと純粋な規則

`cabal build all --enable-tests --offline`はGHC9.14.1、h-raylib6.1.0.0で成功。
所有コードと同梱alphaのライブラリーは`-Wall -Wcompat -Werror`です。
`cabal test all --offline --test-show-details=direct`で全4 suiteが通りました。

`tools/check-api.ps1`は公開APIだけを読み込む4つのクライアントを作り、
Game/Sessionの隠したフィールド、Boardコンストラクター、Read Gameに触れる

`python tools/formatter.py check`は所有Haskell全12ファイルで成功しました。
`docs/vendor-hashes.json`の全9ファイルは元のalphaとバイト単位で一致します。

## 独立監査が見つけた反例

独立した読取専用監査は、同じリプレイ関数同士の一致だけでは見つからなかった
次の問題を再現しました。修正後、同じ反例と隣接例を再実行し、10件すべてが
通りました。コードは`comparison/audit`に保存しています。

- 刻みがまだ進まない描画で、左右キーを押して離すと短押しが消えた。
  OSの押下を列に残し、長押しの初回移動と重ねないようにしました。
- DAS直前に刻みを挟まず離して押し直すと、押下とDASが同時に動いた。
  新しい押下で繰り返しの待ち時間そのものを開始し直します。
- 使用済みholdをもう一度押すと、その後のdropまで捨てていた。
  holdが成功したときだけ、その刻みの残りの操作を終えます。
- 保存の履歴が単なる入力prefixなら、途中の位置をピース出現点だと偽装できた。
  現在は本番の受付・更新から履歴を組み立て直し、順序と各出現点を照合します。
  保存した通知も実際に出た通知の連続した末尾であることを検査します。
- 受付で拒否した入力をSessionが履歴に残し、自分の保存を再開できなかった。
  拒否では元の状態と履歴を保ちます。

別記のセル表・down-positiveのkick表による独立oracleでは、6盤面上の
9,408姿勢と57,502回転を照合し、不一致0でした。これは有限の回転検査であり、
全ゲームの形式証明や公式ガイドライン認証ではありません。

最後の境界確認では、未消去の満杯行を持つGame checkpointを拒否しました。
そのような盤面を許すと、次の固定で4行を超える消去を起こせるためです。
Cavity/TopOutの見本も満杯行を使わず、安定したGameの条件を満たします。
空洞の反例はT/R0/原点(1,22)で、形が収まり、下に動けない接地姿勢であっても
出現位置からは届かないことを確認しました。現在のJSONにはfits/support/reachの
三つの結果と対象姿勢があります。修正後の全4 suiteは64 core/27 hostを含め成功。

## 実ウィンドウ、入力、音

実h-raylibウィンドウからtitle/play/clear/pause/study/resultsを撮影しました。
修正後の600描画のcaptureは終了コード0、3.73秒で完走しました。これは
撮影用に入力を渡した経路で、性能ベンチマークやOSキー入力の証拠ではありません。
初回撮影で通常画面の調査候補の混入、ピースの初期不可視を見つけて修正し、
文字サイズと操作案内も実画面の点検後に改訂しました。

`tools/native-smoke.ps1`はWindows SendInputから44イベントを送り、通常の
キー読取側が9押下edge、125長押し描画を観測しました。移動・回転・落下、
hold、保存・復元、調査の選択・経路再生、巻き戻し、停止、タイトル、設定、
helpを通り、音量60の永続化も確認しました。別の実Space入力でNearSprintが
1刻み目に40行・11,200点・Wonになり、終了させたdropで結果画面を閉じませんでした。
この検査は自動固定の30刻み目より前に終了することを条件にしています。
古いsmokeの30刻み目の終了では、Spaceと自動固定を区別できなかったためです。

9つのWAVはmono/22,050Hz/16bitで、全波形に非ゼロ振幅があります。
WASAPI音声デバイスの初期化、8 cueのロード成功、通常キー実行で36回の
playSound呼出し、BGMの開始を確認しました。原曲は96BPMのminor/add9の
和音・短いモチーフ・柔らかなpulseで生成します。データと再生経路の検証であり、
人が聴いた音質を確認したという主張ではありません。

親担当の独立した実操作でも、保持時間を加えない短いキー入力を使い、P、
1セルの左右移動、回転、hold、Q、候補1→2の選択、選んだ列へ経路を再生して
固定する動作、巻き戻しを確認しました。経路中は37.48秒で時間が止まり、
巻き戻しでは前のJ出現時の20秒に戻りました。46秒の停止盤面をF5で保存し、
別の盤面・時間へ巻き戻した後にF9で盤面・queue・停止時間が戻りました。
help、settings、fullscreen往復、タイトル復帰も確認されています。
この記録には実フォーカス喪失による停止1件、音声再生21回が含まれます。
読みやすさの改訂も親担当が実画面で受け入れました。

親担当が確認した当時のexe SHA-256は
`1370acf7d1e3aa11bcdfa9e9c8ee80a2e95b7ff47c221bbc97ba2d8b4065bdc4`です。
その後、保存包みの27境界検査とDAS/ARRのミリ秒表示を追加して最終ビルドしたため、
配布exeは別のハッシュになります。最終版の起動はパッケージ検査で確認します。

独立した短いOS tapでは、停止画面のP/Tを取り逃すhost側の問題も見つかりました。
`isKeyPressed`による状態の比較をやめ、`getKeyPressed`のイベント列を順番に
取り出すように修正しました。メニューも同じ列を使い、P→Tのような入力は
先に停止を反映してからタイトルへ戻します。長押しは別に採取します。
修正後、個別の短いPで停止・再開、Qで調査、PageDownで候補変更、Tでタイトル、
O/Escで設定の出入り、F1、左右・回転・dropが実画面で動くことを確認しました。
長く押すSendInputだけを通した初回smokeでは、この問題を区別できませんでした。

## 再実行と記録の場所

```powershell
cabal build all --enable-tests --offline
cabal test all --offline --test-show-details=direct
pwsh -NoProfile -File tools/check-api.ps1
pwsh -NoProfile -File tools/native-smoke.ps1
pwsh -NoProfile -File tools/package.ps1
```

このWindows管理環境では、共有Cabal cacheとWindowsアプリ起動に許可された
owner-host実行経路が必要でした。制限された経路でプロセスが終了した事象を、
DLL不足やゲームのクラッシュと混同していません。

詳細ログは無視対象の`.runtime/evidence`と`.runtime/package-verification`、
元の撮影・OS操作は非公開の当時の操作記録（この公開版には含めません）にあります。
配布ZIPの内容検査、別作業フォルダー・WindowsのみのPATHからの展開版起動は
最終packageでも通りました。`tools/package.ps1`がビルド・音声生成・DLL検査・
staging・ZIP作成・展開検査を行い、最後のnotice修正後には`-SkipBuild`で再実行しました。

最終ZIPは`release/PURE-FALL-win64-1.0.0.zip`、6,747,647 bytes、19項目です。
SHA-256は`533e761e805af1da0f1e29f0d774f56939cc03c48eada68060ffb73566e326cb`。
実行ファイルは30,572,032 bytes、SHA-256は
`fdca1d47a2aa2936b3c5ab1ea82821a493ae2903cfcc39e0ca9736c602449a1b`です。
build・stage・展開版で一致し、最終noticeもソースとstageで一致します。
必要なDLLはすべてWindowsのシステムDLLで、追加のDLLはありませんでした。
stageと展開版をTEMPからWindowsだけのPATHで起動し、どちらも終了コード0、
4行消去、8 cueのロードを確認しました。プレイヤーにHaskell環境は不要です。

入力・描画が同じ直前のpackageの600描画captureも終了コード0、3.54秒で完了し、
全6画面を撮影しました。その後は保存拒否条件と見本盤面だけを修正し、
最終版では上記の配置・展開smokeを実行しています。WAVの9個のヘッダー・非ゼロ振幅とハッシュは
`audio-verification-final.csv`にあります。終了時にはゲームの窓が残っていません。
この検査はこのWindows機のローカル配布品質を確認するもので、複数のGPU・OSでの
認証や人による聴取の代わりにはなりません。
