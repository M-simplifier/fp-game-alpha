# Red Dune acceptance

Use `tools/check.sh smoke` for current rule, construction, logistics, boundary,
legacy-import, host-lifecycle and public API checks. Native Windows consumers
use `live-native` and `test/check_native_api.py` through the native project.

`tools/check.sh campaign` explicitly runs the longer physical settlement and
recovery scenarios. Objectives require new production, delivery, consumption,
construction and repair through ordinary commands and ticks. Finite smoke
checks do not establish the 66-hour/42-hour endings, performance or human play.

Use the [current verification record](../../../CURRENT-VERIFICATION.md) for
actual executions of the maintained toolchain. Past per-hour traces and one-off
CPU/allocation records are available in Git history; they are not current gates.
