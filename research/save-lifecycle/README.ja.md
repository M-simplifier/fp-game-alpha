# セーブ・ライフサイクル: TLC と実 Haskell の再現実験

[English](README.md) · [保証範囲](../../docs/guarantees.md#save-lifecycle-with-tla-and-haskell-traces)

固定した Colony 0.2 のコア、TLA+ モデル、13 項目のトレース、元のフィクスチャを
そのまま公開した、有限範囲のプロトコル実験です。通常のゲームビルドとは独立して
実行できます。現在のゲーム全体や UI、任意の実行の正しさを証明するものではありません。

## 実行方法

Linux/POSIX、Python 3.10 以上、**GHC 9.6.7** と付属パッケージ、**Java 21** が必要です。
Cabal による追加パッケージのインストールは不要です。過去の実験は GHC **9.6.6** を
使用しました。今回の公開ランナーによる結果は、別途検証する新しい 9.6.7 系の結果です。

```sh
# 入力の同一性と実行環境を検査。ダウンロードやコンパイルはしません
sh research/save-lifecycle/scripts/reproduce.sh doctor

# Python のみでランナーとパーサーの失敗検出を検査
sh research/save-lifecycle/scripts/reproduce.sh self-test

# 毎回、新しい書き込み可能なディレクトリを指定
RUN_DIR="$PWD/.build/save-lifecycle-01" \
  sh research/save-lifecycle/scripts/reproduce.sh check

# 同じ実行の入力・ログ・成果物と個別の判定を再検証
RUN_DIR="$PWD/.build/save-lifecycle-01" \
  sh research/save-lifecycle/scripts/reproduce.sh verify
```

`PYTHON`、`GHC`、`GHC_PKG`、`JAVA` で実行ファイルを指定できます。
値は実行ファイルのパス 1 個であり、引数付きのシェルコマンドではありません。
`--run-dir PATH` は `RUN_DIR` より優先します。省略時はリポジトリ内の無視対象
`.build/save-lifecycle` を使用します。呼び出すカレントディレクトリには依存しません。

すでに実行結果があるディレクトリは上書きしません。失敗後も新しいディレクトリを
指定してください。ただし、検証済み jar だけを `tools/tla2tools-v1.7.4.jar` に置いた
ディレクトリは使用できます。ダウンロード、ビルド、モデル状態、生成トレース、
実際の保存データとログはすべて `RUN_DIR` 配下に隔離します。

唯一の外部ダウンロードは [公式 TLC v1.7.4](https://github.com/tlaplus/tlaplus/releases/tag/v1.7.4)
の jar です。TLC は 2.19 と表示されます。リポジトリへの同梱やシステム全体への
インストールは行いません。SHA-256 は次の値に固定しています。

```text
936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88
```

異なるハッシュやネットワークエラーは失敗になります。オフライン実行では、この
同じ公式 jar を別途取得して上記の場所に置いてください。チェックサム検査は省略しません。
`scripts/fetch-tlc.sh` で取得と検証だけを行うこともできます。

## 検査する内容

**42 個の名前付き実行結果**を、終了コードと診断内容の両方で判定します。

- 安全性: 生成 **583,932 状態 / 相異なる 79,227 状態 / 未探索 0 状態**
- 公平性ありの活性: ストレージ処理とコールバックの弱公平性のもとで終了すること。
  保存の成功や応答時間の上限ではなく、失敗での終了も含みます
- 公平性なし: 期待される活性反例、TLC 終了コード **13**
- Epoch・Active・Persist の変異モデル: `NoStaleSaved`・`UniqueResponse`・
  `NoFalseSuccess` の対応する反例、終了コード **12**
- 3 反例を元の Haskell 実装と実ファイルの保存・読み戻しで再生し、各状態の
  **全 13 項目**を比較。生成した反例は固定フィクスチャとも一致することを確認
- 正常な 8 トレース、計 **78 状態**を既存の `Init` / `Next` で検査。
  修正済みの Epoch・Active の 2 トレースも検査
- 3 変異トレースを正しい `Next` がデッドロックとして拒否、終了コード **11**
- 完了済みの同一チケットを再利用すると古い重複応答が新しい要求に一致してしまう、
  チケットの新鮮さに関する前提の検査
- 欠損フィールド、整数位置の真偽値、Python `-O`、型が不正な参照トレースの拒否

Persist の修正は実験用の呼び出し側ゲートです。コア自身が保存段階を検査することの
証拠ではありません。修正後の拒否コールバックはモデルの有効なイベントではないため、
その修正トレースを `Next` で検査済みとは扱いません。変異トレース自体は検査して拒否します。
Epoch 変異は完全な識別子比較を通し番号のみの比較に弱めます。

有限範囲は 2 エポック、各エポックで新鮮な要求 ID 2 個、編集最大 1 回、同時に有効な要求
1 個です。TLC は `-workers 1 -seed 1 -fp 0`、最大ヒープ 512 MiB を維持します。
各プロセスのタイムアウトは 180 秒で、超過時は子プロセス群ごと停止します。
原版パーサーのアサーションを無効にする Python の最適化モードは使用できません。

## 結果の読み方と限界

`RUN_DIR/evidence.json` に、実際のバージョンとパッケージ、実行引数、終了コード、
タイムアウト、各判定、入力・ランナー・生成物・ログのハッシュを記録します。
ローカル絶対パスは `$RUN_DIR` などへ置換します。`logs/` がログ、`work/` が隔離コピーと
生成モデル、`build/` が実行ファイルと TLC 状態、`storage/` が要求別の保存領域です。
ソースツリーや共有 GHC 環境を書き換えません。26 件の自己テストは一時ディレクトリを使用します。
成功した実行後、検証器の 12 件の改変拒否テストも追加で実行できます。元の実行結果は変更せず、
RUN_DIR 内の一時コピーを使い、`verification-negative-controls.json` を同じ RUN_DIR に出力します。

```sh
python3 -B research/save-lifecycle/tests/verify_receipt_controls.py \
  --run-dir "$PWD/.build/save-lifecycle-01"
```

全体の `passed-scoped` は、有限検査と意図した負例の再現がすべて成功したという意味です。
個別には期待する反例、予期しない受理、unknown、タイムアウト、ツールエラーを区別します。
任意の非ゼロ終了を期待する反例として数えることはありません。

[公開検証記録](evidence/public-validation.json) は、新規実行から機械固有の情報を除いた
記録です。過去の非公開環境・ログの転載ではなく、ご自身の完全な `RUN_DIR` の代替でもありません。

[provenance.json](provenance.json) は固定入力 **49 ファイル**のサイズ、SHA-256、
Git blob SHA-1 を記録します。コア 25、モデルと設定 7、フィクスチャ 14、Haskell
ドライバー 2、パーサー 1 ファイルです。公開ランナーと文書は新しい移植版として区別します。

対象は要求ごとに保存領域を隔離した単一の直列呼び出し元です。共有書き込み競合、
キューの統合、プロセス停止・電源断、再接続、UI・ブラウザ・モバイル、現在の実製品への
統合、任意サイズのモデル、独立証明証書、任意の Haskell 実行との精緻化関係は保証しません。
TLC のフィンガープリント、変換とパーサーの対応、コンパイラ、保存の抽象化、公平性の
前提も信頼境界に残ります。
