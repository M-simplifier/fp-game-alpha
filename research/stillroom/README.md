# Stillroomで学ぶ、生成される風景と途切れない音

列車の窓から湖が見え、岸へ近づくと水音が増える。降りて歩いても、さっき車内から見た木と同じ木がそこにある。作業画面に戻ると景色は止まり、音楽は続く。Stillroom は、この一続きの体験を Haskell で組み立てた Windows 用の音楽アプリです。

ここでは、風景を必要な場所ごとに作る方法、同じ形を複数の視点から描く方法、必要な時間区間の音を作る方法を調べます。実装を読む入口と、別のゲームへ持ち込む際に確かめたい条件をまとめました。参照する実装は [Stillroom v0.12.0](https://github.com/M-simplifier/stillroom/tree/v0.12.0) にあります。

## 一つの場所を、何度でも確かめる

たとえば世界の seed を `1` にして、座標 `(22, -512)` の地面の高さを問い合わせます。途中で別の seed の世界を問い合わせても、最初の seed と座標へ戻れば同じ高さが返ります。描画側は、この規則を格子状に調べて、周囲の地面を三角形にします。離れて不要になった区画を捨てても、同じ seed と区画番号から作り直せます。

音楽でも、開始サンプル位置と長さを渡すと、その区間に必要な発音を選べます。44,100 Hz の音なら、`882000` は開始から20秒の位置です。そこで必要な音を調べると、今鳴り始める音だけでなく、以前に鳴り始めてまだ響いている音も含まれます。作曲は全履歴を伸ばし続けず、周囲の小節を調べて行います。

二つに共通するのは、必要な範囲を指定して、定まった規則から結果を得ることです。ただし、渡すものと保証することは異なります。

| 場面 | 渡すもの | 得られるもの | 残しておくもの |
| --- | --- | --- | --- |
| 地形を調べる | seed、世界座標 | 高さ、生息域、樹木や岩の配置 | 世界を識別する seed |
| 周囲を描く | seed、区画番号、近景／遠景 | 地形・植生・水面の有限な描画用データ | GPU に転送した近景49区画・遠景81区画までのキャッシュ |
| 音楽を作る | 曲調、seed、開始サンプル、長さ | 必要な発音とステレオ PCM | 読み込み済みの音色、再生位置 |
| 車輪や水音を作る | 乗車状態、速度、森の度合い、岸までの距離、直前の音の状態 | 次の PCM と更新された状態 | ループの位相、音量の推移、走行距離など |

最後の行は、現在地だけでは決まりません。同じ速度に達しても、そこまでどれだけ走ったかで車輪音の再生位置は違います。また、切り倒した木や掘った穴を残すゲームなら、元の seed に加えて変更の記録が必要です。空間と時間の問い合わせを共通の API にまとめるには、こうした履歴をどこに持たせるかも決める必要があります。

## 静かな体験を作るための判断

Stillroom の中心は、音楽と静止した作業画面、短い休息、作業への復帰です。旅の風景だけを独立したゲームとして捉えると、実装の理由を読み違えます。列車は操縦課題を増やさずに景色を変える手段であり、徒歩は同じ場所を自分で見に行く手段です。風景の seed と位置を保存し、休息のたびに別の世界へ飛ばさないことも、その体験の一部です。[製品の説明](https://github.com/M-simplifier/stillroom/blob/v0.12.0/README.md)、[旅の設計](https://github.com/M-simplifier/stillroom/blob/v0.12.0/docs/journeys.md)を参照してください。

固定カメラの湖では、手前の草や左右の木が、開けた水面を囲みます。三つの風景は色違いに留めず、湖盆、山稜、小川という地形の組み立てを変えています。音楽も、決められた和声や音の間隔の中で小さく変化します。試聴では、繰り返す塊の和音を別々に入る声部へ変え、ピアノの下へ単純な拍を足す案は採用しませんでした。これらは作品ごとの選択です。すべてのゲームを静かにする規則や、集中力・健康への効果の証明にはなりません。[風景の設計](https://github.com/M-simplifier/stillroom/blob/v0.12.0/docs/procedural-landscapes.md)、[音楽の設計](https://github.com/M-simplifier/stillroom/blob/v0.12.0/docs/builtin-world.md)に判断の背景があります。

## Haskell が担当する範囲と、依存するもの

v0.12.0 では、seed 付きの場、地形や植物の生成、GPU 資源の寿命、描画パスの実行を Haskell が担当します。音楽の構成と PCM の合成も Haskell です。GPU 上の計算は GLSL と OpenGL、描画・音声デバイスへの接続は固定した h-raylib／raylib、Windows の統合部分は C を使います。「Haskell で担当する」と「外部のネイティブ実装がない」は同じ意味ではありません。[構成と固定した依存関係](https://github.com/M-simplifier/stillroom/blob/v0.12.0/stillroom.cabal)を確認できます。

コードと独自の生成物は MIT ですが、音色のすべてが MIT というわけではありません。ピアノに使う加工済み Salamander 録音は CC BY 3.0、フォントは SIL OFL 1.1、依存ライブラリにもそれぞれの通知があります。別の作品へ素材を持ち込む際は、[素材の来歴](https://github.com/M-simplifier/stillroom/blob/v0.12.0/docs/assets.md)と[組み込み音源の通知](https://github.com/M-simplifier/stillroom/blob/v0.12.0/licenses/builtin-audio.md)をたどってください。
