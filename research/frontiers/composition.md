# 手順を組み替える前に、時間・情報・資源を何として残すか

コインの表裏を当てるゲームを考えます。先に答えを選んでから公平なコインを投げれば、
最良の成功率は1/2です。先にコインを見てから答えを選べれば1です。両方とも、
答えとコインの組は四通り、成功・失敗の葉は`[True, False, False, True]`です。
最後の値だけを比べると、プレイヤーに何をさせたゲームなのかを失います。

この資料は2026-10-26のFree研究と2026-11-05の圏論探索を、公開した実装・有限モデルへ
結び直したものです。ゲーム全体を一つのDSLへ統一する決定や、採用済みの次世代
アーキテクチャではありません。[Freeの操作つき解説](../../site/studies/free-monad.html)は
具体例から構文と解釈へ進み、[時計と到達の図](../../site/studies/clock-and-reachability.html)は
省いた状態が次の一手を変える例を示します。

## 純粋なStepがすでに持つもの

alphaの[Game.Transition](../../libraries/game-transition/src/Game/Transition.hs)は
`Step s i o = i -> s -> (s,o)`で一入力の更新を計算します。入力を固定した遷移は
順序を保って合成でき、入力列は再生・トレース・比較できます。
[Arena](../../libraries/game-arena/src/Game/Arena.hs)は選択を元のkernel入力へ受理し、
観測履歴を受け取る`Policy`を持ちます。[有限解析](../../libraries/game-arena/src/Game/Arena/Finite.hs)は、
制御者に応じて存在・全称の分岐を扱う完全情報・手番制のグラフを受け取ります。
Freeを加えて同じ更新や出力列を書き直すだけでは、この基盤に新しい能力を足した
証拠にはなりません。

入力の内部も自由には切り分けられません。たとえば[Tapline](../../references/tapline/src/Tapline/Domain.hs)は
一つのFrame中でResetを受けると、残りのcommandを捨てます。
`[Reset, TogglePause, Tap J]`を一入力で渡す場合と、Resetの前後を別入力にする場合は
結果が違います。命令を細かくして合成するなら、元の入力のまとまりや取消範囲を
残す必要があります。細分化そのものは意味を保存しません。

## Freeで保持したいのは、返答を待つ続き

「扉を調べ、閉じていれば鍵を探し、開いていれば進む」という手順では、
調べる前に後半を一本の実行済みリストとして確定できません。Freeの一つの表し方は、
命令に対して、許される返答ごとの続きの関数を保持することです。
公開した[AlphaFreeWitness.hs](free/AlphaFreeWitness.hs)は`ChooseBit (Bool -> next)`と
`FairCoin (Bool -> next)`だけで、その依存を小さく確かめます。

命令`c`の返答集合を`R(c)`とすると、命令一段は`F X = Σ_c X^R(c)`、有限で全域な
手順は`T A = A + F(T A)`と書けます。`A`を返して終えるか、命令を一つ出し、返答から
次の手順へ進む形です。各命令をどう読むかを決めれば、その読み方を手順全体へ
再帰的に延ばせます。実行、全応答の探索、説明用の表示へ同じ未実行手順を渡したい
ときに、この構造が候補になります。

応答がunit一種類で、命令が記録するだけなら、有限の`Free (E × -) A`は
`[E] × A`へほどけます。Freeにしただけで分岐や知識を増やしたことにはなりません。
返答依存の段階を普通のphase付きreducerで書くこともできます。比較すべきなのは
表現可能性そのものより、同じ作者の手順から複数の意味を導くときの重複と誤りです。

継続にHaskellの関数を格納すると、そのまま`Eq`・表示・保存を得られるわけでも
ありません。Boolの有限例なら両方へ関数を適用して木を見られますが、無限応答、
停止しない手順、動的な資源、並行実行へそのまま広げた検証ではありません。

## コインの順序だけで、見える情報は決まらない

有限witnessは次を有理数で計算します。

| 問い | 成功率 |
| --- | ---: |
| 答えを選ぶ → 公平なコイン | 1/2 |
| コイン → 結果ごとに答えを選べる解釈 | 1 |
| コイン → 結果を見ない共通の答え | 1/2 |
| 既存alphaのPolicyへunit観測を渡す | 1/2 |
| 既存alphaのPolicyへコインの値を渡す | 1 |

`max_guess E_coin`と`E_coin max_guess`では、選べる時点と情報が違います。
ただしコインが先に発生しても、それを秘密にしていれば、同じ観測を持つ分岐で
同じ答えを選ばなければなりません。`bestChance`は各分岐で自由にmaxを取るので、
完全情報の解釈です。Freeの型が観測制約を自動で課したわけではありません。
既存の`Policy`でも同じ値が計算できることをwitnessに含め、状態を覗く戦略が
`observationRespecting`で拒否されることも確かめます。

同じ問題を確率なしで示すのが、[有限Pythonモデル](category/finite_witness.py)の
じゃんけんです。BがAを見ずに確定するなら、純粋方策は三つの定数だけです。
Aを見てからBを選べるなら、三入力から三出力への関数は27あります。終端の手の組は
どちらも九組ですが、すべてのAに勝つBの方策は前者で0、後者で1です。
どちらも因果的な手順として書けても、許す方策が違います。

したがって、結果集合や一回のtraceの一致は、戦略の保存より弱い条件です。
選択を確定する前に何を観測できるかと、変換前後の許される方策の対応を別に
記述する必要があります。現在の`FiniteArena`を不完全情報・確率・同時手の万能solverと
扱わず、その差を次の実装課題に残します。

## 時計を消すと、何を主張できなくなるか

四部屋を一刻みずつ進み、最後の扉は到着時刻が4の倍数のときだけ通れるとします。
時刻を消した探索は三回で出口を候補にします。しかし実行では3回目の前進が止まり、
4回目で通れます。部屋2・時刻2と、部屋2・時刻3は同じ場所に見えても、
次の「進む」の結果が違います。

状態を小さくする写像を`q`とすると、正確な変換を名乗るには、許された入力について
`q(step(s,a)) = step'(q(s),a)`のような局所的な条件を立てます。
時計を削る写像ではこの例の等式が壊れます。一方、実行可能性を広めに含む解析なら、
余分な候補を返すこと自体は許せます。その場合、候補から実際の成功を断定できない
という使い方の契約が必要です。

有限モデルは時刻0〜8の各期限で、層ごとの計算と全511操作列の総当たりを照合します。
状態を単に別の整数へ符号化する64遷移は元と一致し、時刻を消す場合との違いを
具体的に示します。この小例は一般のゲームの同値証明や性能比較ではありません。

## 同時に置く物と、失敗しても残す物

配列の[配置関係](README.md)は、セル側と配置側の条件を同じ表から求められます。
しかし一つずつ合法な二配置でも、互いに同じセルを使えます。
共有する鍵、弾薬、GPU領域のような資源も、部品単独の正しさだけでは共同利用の
安全を決められません。部品の合成と、表現・解釈を取り替える操作を分けて考えます。

Freeの法則も、失敗時に何を戻すかを決めません。Haskell witnessは同じ
「1を書き込む → 失敗」の手順を二つに解釈します。
`S -> Either E (A,S)`では失敗結果に仮状態がなく、
`S -> (Either E A,S)`では失敗しても1が残ります。
これは純粋に計算した仮状態の例で、送信済み通信や再生済み音を取り消す仕組みではありません。

[Red Duneの在庫取引](../../references/red-dune/core/Colony/Inventory.hs)はすでに
stateとfailureを合成し、[車両割当](../../references/red-dune/core/Colony/Transport/Dispatch.hs)では
失敗した予約等を戻しても、試行予算や次に試す位置は残します。Freeへ変更するなら、
その区別まで保つ必要があります。下位手順を包む取消やresource scopeは、一次命令を
単に足すだけでは表せない場合もあります。

音声や描画では、作者が編集する意味、検査済みの実行plan、動作中の状態を分ける
考え方が候補になります。ただし音声buffer境界でのplan採用と状態移行の成功は、
ゲームの締切やGPU完了の証明ではありません。実行先ごとの時計・所有・終了条件を
調べる課題として残します。これもゲーム側に採用済みの実装を示す記述ではありません。

## 有限例を再現する

リポジトリのルートで、GHC 9.14.1とPython 3を使います。外部のFreeパッケージは不要です。

```powershell
runghc -XGHC2021 -ilibraries/game-transition/src -ilibraries/game-arena/src research/frontiers/free/AlphaFreeWitness.hs
python research/frontiers/category/finite_witness.py
```

Haskellは情報・選択順序・失敗時状態に関する9検査を行います。Pythonは関係とBoolean行列の
合成256件、到達集合1536件、配置の随伴1024件、条件交差4096件、時刻付き操作列511本、
符号化64遷移、観測を制限した30方策を検査し、`finite-results.json`を作ります。
検査の数は実装範囲を示すもので、普遍的な定理や一般ゲームへの転移を保証しません。

次に価値を確かめるなら、一つの返答依存の手順を普通のreducerと並べ、操作を追加した際に
実行と解析が同じ定義を使えるか、情報漏れや誤った時計の省略を拒否できるかを比べます。
正確なコンパイル、可能性を広めに返す解析、意図して規則を変える設計を、同じ「変換」と
呼んで混ぜないことが、その比較の前提です。
