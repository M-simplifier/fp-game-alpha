# 配置、操作、時間を三つの実装で読み比べる

画面の下に空洞があり、T字の四セルがちょうど収まるとします。そこへTを描けることと、
いま上から落ちているTを運べることは違います。さらに運べる操作列があっても、
固定までの時間に間に合うとは限りません。APL、Prolog、Haskellの三つの独立した
落ちものゲームでは、この区別を実際の盤面と操作で確かめられます。

ここには2026-11-06までに選別した作者作成の実装と解説を収録しています。
三作品を同じゲームに作り替えず、それぞれの規則、表現、検査を残しました。
alphaを置き換える統一エンジンや、採用済みの言語別分業を意味しません。

## 三種類の「可能」を分ける

**合法配置**は、四セルが盤内の空きセルにあるという条件です。浮いた姿勢も含みます。
接地まで要求しても、屋根と壁で囲まれた空洞には、上から入る道がありません。
三作品ともこの種の反例を持ちます。Prologの屋根つき例は合法・接地に成功しても
628姿勢の到達集合に目標が現れず、屋根を外すと経路を返します。

**到達可能性**は、開始姿勢から通常プレイと同じ移動を有限回つなげられることです。
通常プレイでは最初に成功した壁蹴りだけを使うのに、探索で全kickを選べるなら、
実行できない解を返します。向き番号も重要です。Prologでは同じ四セルを占める
二つのIの表現が、同じ右回転の後に異なる四セルへ進む反例を残しています。
表示候補をまとめる段階と、探索状態をまとめる段階は分けます。

**時間内の到達**では、重力、残り固定時間、入力の受付と反復も状態に入ります。
三作品の観察・調査は時計を止めるため、その操作列を通常プレイで間に合わせられる
証明にはなりません。[周期扉の図](../../site/studies/clock-and-reachability.html)は、
時計を消すと3刻みで候補が出るのに、実行には4刻み必要となる最小の例です。

## 配列でまとめると、何が共通になるか

APLでは各姿勢が覆う四セルを`Foot[7;1300;4]`に並べます。盤面をこの索引で読み、
四セルが全部空いているかを縮約すれば、姿勢全体の合法性が求まります。
縦の判定列が`1 1 0 1 1`なら、後半の合法な空洞へ飛び越えてはいけません。
prefix ANDで`1 1 0 0 0`を作り、連続して通れる範囲だけを落下に使います。
行消去は満杯でない行を順序を保って圧縮する別の配列操作です。

配置集合`X`の覆うセルを`D(X)`、空きセル`F`へ完全に収まる配置を`E(F)`とすると、
`D(X) ⊆ F ⇔ X ⊆ E(F)`となります。この随伴は、セル側の条件と配置側の条件が
同じ意味を持つことを説明します。ただし、二つの配置がそれぞれ空き領域に収まっても、
その二つが互いに重ならないとは限りません。部品を同時に置くには別の関係が必要です。

この実装がまとめるのは、一つの小さく密な盤面に対する候補です。形と寸法が固定なら
セル索引を再利用できますが、一点だけの衝突判定なら四セルを調べるだけで足ります。
可変個数の主体、疎な関係、生成と削除、連続空間、並行更新まで同じ方法が有利かは
未検証です。ECSを格納・実行方法の候補として検討することと、配置関係でECS全体を
説明できたと主張することは違います。

## 同じ一手を通すことと、正しい一手であること

PURE / FALLはalphaの`Step`、`Machine`、`Arena`を直接継承しています。
受理した入力は元のStepを一度呼び、通常プレイ、方策、再生で規則を書き分けません。
これは複数の経路が同じ規則を使う根拠です。一方、その規則自体を誤って書いていれば、
経路の一致だけでは発見できません。独立した28姿勢・kick表を持つ回転oracleと、
短押し・保存改ざんの反例を、元の形でソースに含めています。

Prologの解説はJavaScript版の探索器ではなく、実Prologが検査した経路・フレーム・
制約の答えを動かすviewerです。再生成器とsource hashを含めました。APLの操作図や
Freeの図は説明用のJavaScriptであり、本番のAPL/Haskell実行と区別します。
有限照合、実ウィンドウの観察、形式的な法則、作者・プレイヤーの判断は、
互いの代わりにはしません。
