# Public research and game-creation site

The Japanese site introduces fp-game-alpha as a reference for the whole
game-development research programme. A reader can follow a question to an
explanation, actual source, evidence and its limits. The independent-game
workflow and the beginner's Station lesson remain separate, visible entrances.
[Repository purpose](../docs/purpose.md) owns that scope; the earlier
[creator-page rationale](../research/public-page/README.ja.md) retains its
original sources and design hypotheses.

The studies include [pure Haskell](studies/pure-fall.html),
[APL](studies/array-fall.html) and [Prolog](studies/prolog-fall.html) Tetris,
[Free programs](studies/free-monad.html), and
[clock/reachability](studies/clock-and-reachability.html). Their interactive
models have their own stated scope; an illustrative browser model is not
automatically an execution of the language or game source it explains.
[Research coverage](../research/coverage.md) records the selected source set.

Edit the catalog rather than generated `research.html`. Its static articles
already contain every summary, evidence statement, limit and source link.
Without JavaScript the full list stays readable. `research.js` adds filtering
and shareable `topic`, `status` and `q` URL parameters; it does not load a remote
search service. The statuses describe implemented work, examples, experiments,
questions and history, not a ranking or a decision to adopt one architecture.

## Static publication and data boundaries

The site uses plain HTML, CSS and JavaScript with system fonts. No build
framework or package installation is needed to preview it. GitHub Pages
publishes `site/` after checks on main; pull requests validate without deployment
permissions. Only the current main revision may deploy, so a completed older run
is skipped. The workflow is maintained in [ci.yml](../.github/workflows/ci.yml).

Existing Stillroom and Afterlight native images load from their public sources
and link back to their source/provenance. Selected study figures retain their
own recorded provenance. Site code is authored under this repository's MIT
license; source licensing does not decide the rights of arbitrary downstream
game assets or binary distributions.

The creator's brief stays in the page and clipboard. There is no form endpoint,
analytics, browser storage or third-party executable script. The saved Station
trace is fetched from this site's own `evidence/` directory. External navigation
and documentary images use their named public hosts.

## Generate, check and preview

Run from the repository root. After changing catalog data, regenerate its page:

```text
python tools/research.py build
```

The current research/site checks are:

```text
python tools/research.py check
python tools/test_research.py
node tools/test_research_ui.cjs
python tools/check_site.py
node --check site/site.js
node --check site/research.js
python -m http.server 8768 --directory site
```

Open the local server to inspect the homepage, guide, catalog, creator, lesson
and changed studies at representative widths. `research.py check` validates the
catalog and exact generated-page correspondence. The Python site checker checks
local assets/fragments, repository links, source/provenance and the saved
accepted/refused trace relationship. The Node research test executes the actual
filtering script against a small DOM fixture, including URL filters, Japanese
search, no results and reset. These checks do not fetch all external sites,
exercise a real browser, or certify accessibility and reader understanding.
Source export and license checks remain part of the repository's publication
gates; regenerating an index does not replace them.

## Station's saved execution evidence

The creator's Station panel presents saved stdout packets from the compiled
Haskell headless player. It is not a live browser port. The inputs are `act 1
local` followed by the same command; the latter is refused by the transport's
visible-turn check. The Domain's own stale-token check is a separate boundary.
See [the source revision and packets](evidence/station-trace.json).

For a new record, build the Station player with [tools/play.py](../tools/play.py),
send those two newline-delimited commands to the executable and capture all
three JSON lines, including the initial packet. Record its exact source revision
and source fingerprint. Keep real output fields rather than reconstructing
them from page copy. A changed current source does not invalidate a pinned
historical record; a new behavior claim needs its corresponding execution.

## Historical browser verification and current claims

The original creator page was exercised in Chrome on Windows on 2026-10-04.
It now lives at `create.html`; this dated record is not fresh browser evidence
for the later research homepage, guide, catalog or studies.

- Desktop and 320/390px viewports had no document-wide overflow at 320px.
- Recorded trace steps were energy 8 → 7 → 7, turn 1 → 2 → 2 and delivered
  0 → 1 → 1. Reset restored the initial packet.
- Copy by click and keyboard matched the brief/target textarea and clipboard.
  The copied instruction retained the brief, source revision, skill path and
  GAME-SPEC/continuation requirements.
- Keyboard skip link/focus, disclosure expansion and manual selection/copy were
  exercised; the temporary viewport override was reset afterward.

The denied-clipboard branch was source-reviewed; manual copying from its normal
textarea was exercised. Permissions were not changed to trigger denial.
The no-JavaScript creator path was source-reviewed, not browser-tested with
scripting disabled: the copy button stays disabled and unnamed fields cannot
submit the brief into a native form URL, while a manual instruction remains.

Record new browser observations with the checked revision, pages, actions,
viewport and limits. Clipboard or filtering success does not establish that a
new reader completed an AI-led game, understood a study, or that the entire
site conforms to WCAG.
