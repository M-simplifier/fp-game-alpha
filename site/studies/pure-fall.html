01

One authoritative stepSpaceを押すと、どこを通るのか

ハードドロップを受け取ると、ピースが着地し、盤面に固定されます。行が埋まれば消え、得点と次のピースが決まります。この一続きの規則を、PureFall.Core.step が一度の更新で処理します。

TickInput押した操作を順番に並べた列
＋ 現在の長押し状態
→
gameStep = Step step入力と現在のGameを受け取り、
次のGameと通知の列を返す
→
Game + [Cue]変わった盤面・得点・時間
＋ 起きた出来事の順序
Game → RenderModel → 画面状態から、セルの役割・数値・予告・着地先を組み立て、h-raylibで描きます。
[Cue] → 視覚効果・音Dropped → Locked → Cleared などの通知を、落下の反応、発光、効果音に使います。

この更新関数はウィンドウを開かず、音も鳴らしません。返り値の Cue は「音を鳴らした」という報告ではなく、「回転した」「固定した」というデータです。実際の描画と再生は、外側のhostが引き受けます。

そのため、画面なしで同じ入力列を渡し、盤面や通知を検査できます。リプレイのために落下や採点を別実装する必要もありません。

-- この作品の中核の型
gameStep :: Step Game TickInput [Cue]

-- alphaのStepが包んでいる関数
input → state → (state, output)
操作の順序にも意味があります。 たとえば回転してから落とす場合と、落としてから回す場合は同じではありません。ピースを固定したら、その刻みの残りの操作は次のピースへ流しません。停止と調査の切替には、別に明示した優先順があります。

02

Time, taps and holds短い押下を残し、60Hzで進める

画面を一枚描くことと、ゲームを一刻み進めることは別です。PURE / FALLの規則は60分の1秒ずつ進みます。描画までの経過時間が短ければ待ち、長ければ必要な刻みをまとめて実行します。

キーを押して離すまでが短くても、OSの押下列に入った操作は捨てません。hostは getKeyPressed を空になるまで読み、順序を保って渡します。「今も押されているか」は、長押しを調べるときに使います。

Session は、まだ渡していない押下と、1刻みに届かなかった時間を持ち越します。複数の刻みを進める場合、押下は消費する刻みに一度だけ、長押しは各刻みに渡します。

整数で、端数を持つ

経過時間の単位はマイクロ秒です。これを60倍して足し、1,000,000たまるごとに1刻み進めます。60分の1秒を毎回の浮動小数点の足し算で近似せず、残った値を次へ渡します。

遅い描画でも、たまった時間は上限で切り捨てません。これは時間の意味を保つ規則であり、負荷や速度の保証ではありません。

描画の間隔を変えてみる

説明用モデル

最初に「右回転」が一つ待機しています。8ms → 9ms の順で押すと、最初の描画で保留した回転が、次の描画の1刻みに届きます。リセットして50msを押すと、3刻みをまとめて進めます。長押しの例は右キーです。

累計の経過時間0ms
進めた刻み0tick
待機中の押下1右回転

残り 0 / 1,000,000 debt単位

まだゲームの刻みは進んでいません。
右回転を一度だけ渡す準備ができています。

これは時間と入力の受け渡しだけを抜き出した図です。実ゲームの動作や性能を測るものではなく、停止・調査・32操作ごとの分割は省略しています。

9 / 2

横移動の待ちと間隔

押した直後に1マス。既定のDASは9刻み、以後のARRは2刻み。新しい押下で待ちを始め直し、押下と長押しによる二重移動を避けます。

30 / 15

接地してから固定するまで

接地後30刻み、約0.5秒で固定。成功した横移動・回転で待ちを戻せますが、1ピース15回まで。失敗した操作では戻しません。

PAUSE

止める境界を決める

停止する刻みに同時のdropを実行しません。フォーカス喪失で直ちに停止し、その描画の時間も加えません。ヘルプや調査中の実時間も除きます。

03

Types and valid states不正な状態を、入口で止める

保存データに「盤面の外のセル」や「ありえないカウンター」があったら、そのままゲームへ戻してはいけません。PURE / FALLでは、値を作る入口と、外から読める情報を分けています。

盤面は10列24行で、上4行を隠して描きます。board は座標範囲と重複を調べてから Board を返します。呼び出す側は内部のMapやコンストラクターを使って、この確認を飛び越えられません。

Game や Session も内部フィールド名を公開しません。単にコンストラクターを隠すだけでは、公開したレコード名で書き換えられる余地が残るためです。Read Game は用意せず、復元関数を通します。

TickNo経過したゲームの刻み
TickSpan何刻み待つかという長さ
FrameMicros描画間の経過マイクロ秒
DebtUnits次の刻みへ持ち越す端数

どれも数値ですが、役割ごとに別の型です。得点や行数の整数とも、そのまま取り違えないようにしています。

回転の前提を揃える

種類と90度回転の遷移ごとにSRSの壁蹴りを定義。画面下向きをyの正方向にしているため、上向き座標の表からyの符号を反転します。180度回転は扱いません。

次の出現も状態に入れる

7種類を一巡させるseven-bagの出現列と、続きの乱数状態を保持。保存・再開後も、ピースの出現順が変わらないようにします。

型の外も検査する

保存時と復元時に値域や時系列を検査。公開APIから隠したフィールドなどへ触れる4つのクライアントが、意図どおりコンパイルに失敗することも確認しています。

型は「この関数には何を渡すか」を狭めます。すべての規則の正しさ、終了、速度まで型だけで証明するわけではありません。回転表の向きのような誤りには、別に書いた表との照合が必要でした。

実装確認Core.board / rotated / restore / validateGame · Timeの4型 実行記録公開API検査・独立回転oracle

04

Visual response and sound絵と音で、一手の結果を伝える

暗い盤面の中で、現在のピース、落下先、固定済みのセルを見分ける。落としたら反応が返り、行が消えたら得点が読める。こうした表現は、ルールから返った状態と出来事を材料に作っています。

現在・固定済み着地予告調査候補
  • 色だけに任せない着地予告は薄い枠、調査候補は琥珀色の太い枠。現在のセルには明るい縁を加えます。RenderModel の CellRole が描き分けの根拠です。
  • 固定と行消しに短い反応を返すLocked で盤面の縁が光り、セルから粒子が出ます。Cleared では行の明滅と消し方・加点を表示。接地中は盤面下の細いバーに固定待ちの割合を出します。
  • 縮めても配置の関係を保つ1440×1000の基準座標を縦横比を保って配置します。本文・等幅文字には最小の基準サイズを設け、実画面の点検で案内と文字の大きさを改訂しました。

8つの出来事に、8つの効果音

移動、回転、drop、hold、固定、行消し、終了、停止。それぞれに短いPCM音を生成します。回転には上がる音、dropには下がる音、行消しには時間差で重なる音を使っています。

同じ描画で同じ種類の通知が複数出た場合、音は一種類につき一度にまとめます。通知列の意味と、音の混み方を調整する処理は別です。

96 BPMのオリジナルBGM

minor / add9の和音に、低音、pulse、短いモチーフを重ねた生成音源です。停止中はBGMの音量を落とし、設定で音量・音楽の有無を変更できます。音源の読込と再生経路は確認済みですが、その記録は人の聴取評価とは分けています。

MARATHON10行ごとにレベルが上がる。続けて積むリズム。
40 LINE SPRINT40行を消すまでの最短時間。終点が明確な一回。
TWO MINUTE有効プレイ時間120秒で得点を競う。
PRACTICE競技記録を更新せず、置き方を試し直す。

05

Reachable, not just empty収まる場所と、届く場所は違う

四つのマスが空いていても、そこへピースを運べるとは限りません。Practiceの調査は、現在の姿勢から一操作ずつ動かし、実際に到達する着地姿勢と、そこまでの操作列を探します。

reachableFrom は姿勢を節点にして、左・右・下・左右回転の5種類を幅優先探索します。回転には本番と同じ rotated、移動には同じ shifted を使います。下へ動けない姿勢だけを着地候補に残します。

返すのは最終座標だけではありません。「左、左、回転、下……」という経路も残します。画面では80msごとにその操作を本番の更新関数へ渡し、最後にハードドロップして固定します。

ここで止めているのは、盤面、現在の1ピース、重力と固定の時計です。時間内にその操作を押し切れるか、ホールドや次のピースまで含めて得か、という問いはこの探索に含めません。

実装の見本T / R0 / 原点 (1, 22)左の図は Cavity の盤面下部です。桃色のTは四マスとも空き、床にも接します。しかし屋根と壁があるため、出現位置からは届きません。
fits: truesupported: truereachable: false
「形が収まる」と「操作で届く」を分ける、具体的な反例です。
幅優先探索は、この固定盤面と操作集合で到達する姿勢を調べます。姿勢は種類・回転・原点で数えるため、同じ見た目のセル配置が常に一つの候補へ統合されるわけではありません。「全テトリスの解」や、最善手の証明を返す機能ではありません。

06

Replay, rewind and persistence一手を戻し、別の続きを記録する

Practiceの Backspace は、直前のピースが出現した時点へ戻します。そこで別の置き方を選ぶと、捨てた操作がリプレイに混ざらず、新しい続きが残ります。

巻き戻しで、操作履歴はどう変わるか

説明用モデル

二つのピースをA、Bの操作列で固定した直後を例にしています。Bを戻してからCで置き直すと、再生に残る列が変わります。A・B・Cは説明用の名前で、実際の保存形式ではありません。

S01個目の出現
→A
S12個目の出現
→B
S23個目の出現
再生する操作列 = A ++ B
現在はS2。AとBを順に再生すると、ここへ戻ります。

Session は、出現点の状態と、その時点までの入力数を最大100ピース分保持します。戻すときには、選んだ位置で履歴を切り、初期状態からその入力列を本番の更新で組み立て直します。

行を消す前の情報を保存しているから戻れます。たとえばJで埋めた1行とIで埋めた1行は、どちらも消すと空になります。空の盤面だけから元を一意に求めることはできません。

リプレイは映像を保存しない

結果画面の R は、その回の初期状態と TickInput の列を使います。同じ tickSession を順に呼び、状態と通知を再び得ます。

alphaの「入力境界を順番に合成する」考え方が、ここではゲームの再生経路になっています。順序を入れ替えたり、一刻みの操作列を勝手に分割したりする法則ではありません。

F5で保存するもの

  • 盤面、得点、現在と次のピース、乱数状態
  • 未処理の押下、長押し、刻み未満の時間
  • 初期状態、操作履歴、巻き戻し先、現在の通知
  • 調査候補の選択、経路再生の残り操作と80ms未満の待ち

F9で確かめてから戻す

  • 形式の版、位置、値域、入力数、サイズを検査
  • 履歴を再生し、現在と出現点の状態を照合
  • 残りの経路が成功し、最後に1ピースだけ固定するか確認
  • 音源・GPUのハンドルや粒子は保存せず、host側で用意し直す

中核の保存文字列は16MB、hostの包みは32MB、操作履歴は100万入力まで。保存側も受理条件を検査し、上限超過なら以前の保存を残して画面に失敗を表示します。保存形式はこのローカル版のv1を対象とし、長期互換は約束していません。

同梱の Game.Arena.Finite は、有限ゲームの別の分析に使うモジュールです。この作品の着地探索は、その固定点計算を流用したものではなく、Core.reachableFrom が持つ姿勢グラフの探索です。

必要な表現を選ぶ

alphaはFRPを必須にしていません。この作品は、保存できる整数カウンターと入力待ちを直接持つ設計を選び、Yampaは使っていません。FreeモナドやECSも追加していません。

大事なのは採用技術の数ではなく、今回のゲームで必要な境界を明確にし、その境界を実際の操作・再開・表示で確認することです。

この作品を「集大成」と呼ぶなら、
一手を更新する小さな核が、遊ぶ・戻す・調べる・見せるところまで届いた、という意味です。

ここで一つの落ちものゲームを完成させたことは、汎用エンジンの完成や、どんなゲームにもこの形が最適であることを意味しません。作品ごとに必要な規則を残しながら、共通にできる境界を確かめた一例として読むのが、alphaの目的にも沿っています。

Evidence and further reading確かめたことと、まだ言えないこと

一つの経路同士が一致しても、両方に同じ間違いがあれば見逃します。PURE / FALLでは、状態の検査、本番と別に書いた照合、実ウィンドウの操作を組み合わせました。以下の数値は、2026-10-26の検証記録にある実行範囲です。

250 seed × 300入力。別の行圧縮モデルとの1,200盤面の比較や、400入力列の保存・再開検査も実行しました。有限サンプルでの確認です。

実際のconsumerOS → GAME

短押しと配布版を確認

実キーの短いtap、調査経路、巻き戻し、保存・復元を画面で確認。展開した配布物も、開発環境のないPATHと別フォルダーから起動しました。

実操作で見つかったことも、設計の一部です。 初回の画面確認では、通常画面への調査候補の混入と、初期ピースの不可視を修正しました。短いキー入力では、長押し中心の確認で見逃した押下の取り逃しも発見しています。テスト件数だけで完成度を代用せず、実際に受け取る画面と入力を確かめました。

付属方策が動くことから、強い戦略や初心者への教育効果は分かりません。テスト通過から楽しさや他言語への理解の転移も結論しません。音についてはデータと再生経路を確認し、性能についても撮影時間をベンチマークとして扱っていません。

この解説自体は、現在のソースと記録を読み直して作ったものです。過去の実行結果は当時のWindows環境の記録として示し、ここではゲームの再実行や新たな性能測定をしていません。
