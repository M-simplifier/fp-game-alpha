# プレイヤーがしたいことから遊びを設計する

プレイヤーが食事の場を好きな場所に建て、料理が届き、住民がそこで食べる
のを見届け、周りに灯りを置く。Red Duneの改良では、この範囲を一度つないだ。
自分の作った暮らしを広げたいという関心に結び付くかを試すためである。
次の作品では、その作品で何を試したくなり、結果をどう受け取るかを考える。

以下は勉強会から編集した設計判断と仮説である。根拠の種類と今回の成果は
[出典と検証範囲](sources.md)に置く。操作や結果が伝わらない場合は
[画面と日本語](ui-and-japanese.md)も読む。

## 作りたい経験と、実装する仕組みを結び付ける

機能一覧より先に、一つの場面を書く。「配送を実装する」なら、何のために
誰へ届け、その変化をプレイヤーがどこで見届けるのかまで考える。
実装された規則、動作中の関係、人が得た経験を分けるのは
[MDAの設計枠組み](https://cdn.aaai.org/Workshops/2004/WS-04-04/WS04-04-001.pdf)
を使った判断であり、分類を埋めれば楽しくなるという主張ではない。

世界が誘う行為を、本当にできるかも見る。
[Agency Reconsidered](https://cs.uky.edu/~sgware/reading/papers/wardripfruin2009agency.pdf)
は、望む行為と計算モデルが可能にする行為の関係を論じる。
「この場所で暮らしを作れる」と見せながら、配置が利用にも景観にも返らない
なら、その約束を狭めるか、働きかける規則が必要になる。
逆に、景観を描く作品では住民の利用まで実装する必要はない。
操作して初めて別の目的を思いつくこともあるため、開始前に目的を言える人
だけを想定しない。

遊べる最小範囲は、その経験を確かめられる大きさで選ぶ。
レースなら入力と走りの感触だけでも核心を試せる。採取と装飾がつながる作品
なら、材料の用途まで一度遊べないと判断しにくい。
[Cozy Groveの制作記録](https://lostgarden.com/2021/12/12/value-chains/)
では、採取単体は不評でも、その先の制作や装飾が材料に価値を与えた。
これは「最小操作は必ず単体で面白くなければならない」への反例である。
ただし、望む結果があれば途中の手間はいくら増やしてもよい、とはならない。

## 迷った理由に合う変更を選ぶ

同じ「次に進まない」でも、直す場所は違う。以下は診断の候補であり、
全項目を毎回点検する表ではない。

| 実際に見た状態 | まず調べること | 変更の例と限界 |
| --- | --- | --- |
| 試したい対象はあるが触り方が分からない | 操作できる面と操作方法が見えるか | 建設できる地面と費用を示す。機能追加だけでは発見しやすくならない。 |
| 指示は出せたが、結果を読み取れない | 受付、進行、実際の成果が対応するか | 到着先で配送や利用を見せる。原因を実装していないなら表示だけで補わない。 |
| 結果は理解したが、もう変えたいものがない | 本人が満足したのか、求める遊びがないのか | 場所や目標の違いを試す。説明を増やしても関心は生まれないことがある。 |

失敗の理由が分かり、次の試し方を考えられるなら、迷いが発見につながる
場合もある。基本操作を隠すことと、どの戦略がよいかを考えさせることを分ける。
[Factorioの導入の比較](https://www.factorio.com/blog/post/fff-261)
には、指示を守っても理解しない問題と、基本操作に気づかず止まる問題の両方がある。

## 最初の成功が、その後に何を残すかを見る

導入では本編と同じ種類の楽しさを、小さく試せるようにする。
[Factorioの導入撤回](https://www.factorio.com/blog/post/fff-342)は、好反応が
あっても、本編が続けない体験を約束した点を問題にした制作事例である。
矢印どおりに一度成功した後、同じゲームで自分の工夫ができるかを見る。

慣れた後には、既知の道具の使い方や目的が変わる余地を考える。
[Fulgoraの作り直し](https://www.factorio.com/blog/post/fff-399)では、場所を
変えて同じ採掘・生産を繰り返す負担を、混じった出力の選別や余剰処理へ改めた。
応用するのは判断の変化であり、全ゲームへリサイクルを足すことではない。
同じ配置でも、自分が望む別の景色を作る反復には価値があり得る。
それを物流上の新しい深さと同一視しない。

暮らしや造形が中心なら、解決済みの仕事を任せ、作ったものを眺める時間も
残す。毎回成功直後に危機を足すと、進歩が追加の義務になり得る。
厳しい生存や競争が中心なら、緊張や効率を求める設計が適する場合もある。
作品が約束する経験と、実際に報いる行動が合うかで選ぶ。
[Against the Stormの住宅変更の撤回](https://eremitegames.com/hubs-update/)
は、生活の場所に意味を足した結果、配置の不安や管理が増えた反例になる。
生活感のために全行程を距離最適化の義務へ変える必要はない。

## 判断を変えられる試遊を行う

現在の仮説に関係する一つの場面を、まず誘導せずに遊んでもらう。
「庭を作りたいはず」と先に目標を与えず、実際に見たもの、試したこと、
結果、その後にしたことを記録する。理由を確かめる質問はその後に行う。
予想や別の配置での試行は理解を調べる助けになるが、成功操作だけで理解を
決めず、理解できたことだけで楽しさを決めない。

例えば、利用を正しく理解した人が景観より物流の改善だけを選ぶなら、その人
について「場所への愛着が主な楽しさ」という仮説を弱める。満足して終えた人
と、混乱や退屈で止めた人を無操作だけで区別しない。長期の価値を主張する
なら、保存した状態へ後日戻り、何を覚え、何を続けたくなるかまで確かめる。

AIの操作、再現記録、CIは規則と操作経路の証拠になる。人間の初見の理解や
楽しさには別の証拠が要る。一度の肯定的な感想はその試遊の有効な証拠として
残し、期間・人数・作品を越えた成功の保証へ広げない。
