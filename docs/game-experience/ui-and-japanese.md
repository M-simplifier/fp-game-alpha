# 操作と結果を画面と日本語で伝える

配送欄の「現在 120／目標 240」だけでは、何がどこにある量なのか分からない。
水ならLを付け、現在量は届け先の在庫、目標量は補充の目安だと伝える。
停止ボタンなら、次の生産を止めるのか、今の作業も止めるのかを区別する。
画面と文言を同じ実状態へ合わせる作業として扱う。

企画や楽しさを判断するときは[遊びの設計](design.md)、根拠を調べるときは
[出典と検証範囲](sources.md)を読む。以下の数値例は説明用であり、推奨の
バランス値ではない。

## 大事な場所、できる操作、詳しい理由の順に見せる

最初の視線では、今触りたい対象や気になる変化が見えるようにする。
対象を選んだら、できる操作とその効果を示す。在庫内訳や詳しい条件は、その
判断に必要になった場所で読めるようにする。これは勉強会で参照した
[Zach Gageの三段階の読み方](https://stfj.net/DesigningForSubwayLegibility/)
を介した構成判断であり、常に三つのパネルを作る指定ではない。

建物を絵に変えても、触れることが伝わらなければ操作は見つからない。
選べる場所、配置予告、接続先、費用などを行為に結び付ける。全状態を同時に
強調せず、出来事が起きたときだけ注目を促す。色だけに意味を任せず、形や
短いラベルも使う。読み取りが難しければ、同時に扱う規則の数も見直す。

文字サイズの定数だけで読みやすさを判定しない。想定する表示サイズで実際の
日本語、改行、切れた行、背景との見分けやすさを確認する。必要な文字や
アイコンを拡大できるかも考える。
[Xboxの文字表示ガイド](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101)
は測定方法と調整の指針であり、楽しさを保証する基準ではない。

## 指示の受付と、世界で起きた成果を分ける

「注文を受け付けた」「材料待ち」「調理中」「届いた」「食べた」は別の事実
である。クリック時に食事が成立したような演出をしない。既存在庫の配送を
直前の別注文の成果として説明しない。表示は実際の状態や履歴から作る。

工程、進めない理由、時間の停止も分ける。「運搬中」と「時間停止中」は同時に
成立し得る。一本道の進捗図を、部分配送や並行作業まである仕組みへ無理に
当てはめない。原因の説明は、プレイヤーが見ている対象の近くに置く。
[Factorioの局所的なエラー表示](https://www.factorio.com/blog/post/fff-261)
は、画面の遠い場所に出た説明が見落とされる問題に対応した制作例である。

表示する数量には、対象、単位、現在値・予定値・目標値の違いを残す。
利用予定6人と、直近に実際に食べた4人を混ぜない。目標に満たないのに
補充しない規則なら、運搬中の量や一回分の補充条件も確認できるようにする。
小数点を増やすより、どの量を見ているかを明らかにする。

## 操作の効果は、短い文でも省かない

次はRed Duneの実装を踏まえた例である。他作品では、その作品の規則に合わせる。

| 曖昧な表示例 | 意味を区別する表示・説明例 |
| --- | --- |
| `停止` | `連続生産を止める`。次の仕事を始めない。進行中の作業、班、配送は残る。 |
| `解除` | `この施設の班を外す`。三交代の担当を外す。作業中は外せないことがある。 |
| `120 / 240` | `水：現在120 L / 目標240 L`。届け先の在庫と補充の目安。 |
| `開始` | 操作の対象を示し、班や配送の準備と時間の再開が起きるなら、その効果も伝える。 |

短いボタンと詳しい説明は分担できる。ただし、押すかどうかを変える費用、
取消・移設の可否、意外な時間の再開などは、押す前に分かる場所へ置く。
同じ施設を「拠点」「ノード」「場所」と都合で呼び替えない。

## 日本語は、内容を決めてから整える

まとまった説明を書く前に、読み手、その場面、分かるべき事実を短く定める。
タイトルと見出しは対象と説明内容から作る。先に決め台詞を置いて本文を
合わせない。一つの具体例を進め、用語が必要になったところで加える。
これは既存の説明スキルを、ゲーム制作で再利用するために編集した指針である。
[文化庁の文章指針](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93731901_01.pdf)
と[SmartHRの修正例](https://smarthr.design/basics/text/)も判断の材料にした。

「暮らしを支える機能」なら、誰が何をすると何が変わるかへ戻す。
例えば「井戸で汲んだ水を荷車が配給所へ運びます」と書く。
「補充目標量の変更の実行」は「補充する量の目安を変えます」と動作へ戻す。
抽象語を外した一件の説明が書けないときは、事実の不足を調べる。

係る言葉を近づけ、条件と結果を読み取れる語順にする。主語は必要なときに
補い、同じ結論の反復や見出し直後の言い直しを削る。本文の文体はそろえる。
短文化は手段であり、一律の字数、禁止語、自然さの点数を合否にしない。
「関数が値を返す」のような自然な無生物主語、必要な受身、創作の詩情は残す。

推敲後は、数値、否定、条件、因果の強さを実装や資料と照合する。
「権限がないと保存できない」を「権限があれば保存できる」に変えると、
元にない十分条件を加える。人の感情や、画面で確かめていない効果も補わない。
最後に装飾を外して日本語だけを読み、実画面で改行と操作との対応を確認する。

## 案内は必要なときに読み、作業へ戻れるようにする

HELPは用語と操作を後から調べる場所にする。短い案内は実際の条件に合わせ、
非表示、再表示、読み直しを選べるようにする。操作の基礎は明確に伝えつつ、
どの場所や戦略を選ぶかは作品の遊びとして残す。
七章という数やRed Duneの導入順を、別作品の必須構成にはしない。

案内を読む間に世界を止める作品なら、閉じた直後の時間の追いつきも検査する。
選択、配置途中の状態、元の画面へ戻れるかを見る。HELPや案内設定の保存が
世界の保存状態を変えないかも、その作品の約束に応じて確かめる。
オンラインなど停止できない作品では、停止を約束せず、読む負担と見逃した
情報へ戻る手段を考える。
